## 范围

- 显式 `--hls`；**不**按扩展名自动识别，队列/浏览器投递的 `.m3u8` 仍按普通文件处理。
- master 播放列表选 `BANDWIDTH` 最大变体；media 播放列表按 `#EXTINF` 顺序取分片；
  `#EXT-X-MAP` 初始化段先下；相对 URI 按 playlist 最终 URL 解析。
- `#EXT-X-KEY:METHOD=NONE` 放行；AES-128/SAMPLE-AES 与 `#EXT-X-BYTERANGE` 明确拒绝。
- 分片顺序写一个输出文件；默认名把 `.m3u8` 换成 `.ts`；不写 `.dlm.json`、不可续传，失败保留半截文件。
- 同源分片沿用 Referer/Cookie/Basic；跨 host 分片不带这三类凭据。

## 测试

- `hls::tests`（6 条）：master 选最高带宽与相对 URI、media 顺序 + METHOD=NONE、加密拒绝、
  BYTERANGE 拒绝、默认命名、跨源凭据剥离。
- `hls_downloads_master_playlist_segments_in_order`：本机 stub 给 master（low=100 / high=900）→
  high media → `a.ts`/`sub/b.ts`/`c.ts`；真二进制 `--hls` 合并结果逐字节等于
  `alphabetagamma`，退 0。
- `hls_rejects_encrypted_playlists`：`METHOD=AES-128` ⇒ 退 1，stdout 含“加密 HLS”。
- `hls_is_refused_with_data_file_or_max_bytes`：两种冲突都退 2，本机监听一个连接都没收到。
- CLI 单测：`--hls` 置 `FLAG_HLS`，与 `--data-file`/`--max-bytes` 互斥。

## 边界

- 不做 DASH、DRM、浏览器媒体嗅探、队列 HLS、断点续传。
- 只支持一层 master → media；不支持 `#EXT-X-BYTERANGE`、加密 KEY、多音轨选择。
- 失败保留半截文件，下次从头开始；`--sha256` 在合并完成后校验。
