# 视频下载：yt-dlp 通路（2026-11-27）

## 定位

`--video` 把地址交给**外部 yt-dlp**，不自己啃站点解析。理由写在 `src/video.rs` 顶部：
视频站的分片/DASH/签名/防盗链不该由下载器重写一遍；而随包分发 yt-dlp 等于把一个
更新极勤的二进制焊进发布物。

`--allow-html` 与 `--video` 是两件不同的事：
前者是"我知道这是网页，就要下网页"，后者是"这是视频页，我要视频"。

## 用法

```
dlm --video --url <视频页地址> [--out-dir <目录>]
```

找 yt-dlp 的顺序：`DLM_YTDLP` → `dlm.exe` 同目录的 `yt-dlp.exe` → PATH。

## 实测（本机真 yt-dlp + 真网络）

```
$ dlm --video --url https://www.w3schools.com/html/mov_bbb.mp4 --out-dir target\video-real
视频：mov_bbb（mp4，体积未知）
  0.1% … 33.1% 66.4% 100.0%
退出码=0
落点：mov_bbb.mp4  788493 字节
```

（进度行在捕获输出里各自成行；真控制台上是 `\r` 原地覆盖。）

## 不碰网络的端到端证据

`tests/bin/fake-ytdlp.rs` 照真实 yt-dlp 的两个约定说话（`--dump-single-json` 交 JSON、
下载时吐 `[download] xx.x%`），用例：

- `video_mode_delegates_to_yt_dlp_and_reads_its_progress`：
  元信息打印「示例 视频 / 2.0 MiB」+ 进度读到 100.0% + 退出码 0
- `video_mode_surfaces_the_tool_reason_when_info_extraction_fails`：
  提取失败时退出码非零，且把 yt-dlp 的原话带出来（不许只说"失败了"）

变异（`parse_progress` 一律返回 `None`）⇒ 两条用例同时红：单测红在解析，
端到端红在「进度要从 yt-dlp 的输出里读出来」。还原后全绿。

## 已知边界

- 只走单条 URL，不做播放列表（`--no-playlist` 写死）
- 格式固定 `bv*+ba/b` + 合并成 mp4，还没有 `--video-format` 开关
- 进度只取百分比，速度/ETA 仍显示 yt-dlp 之外的读数（详情面板那条曲线对视频任务不适用）

门禁 10/10：lib 613 / integration 130。
