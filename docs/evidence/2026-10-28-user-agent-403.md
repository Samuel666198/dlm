# 右键下载“没反应”排查与 User-Agent 修复（2026-10-28）

## 症状

Tabbit 里右键链接选 `Download with dlm`，没有文件落盘，也没有任何失败提示。

## 排查

- **菜单本身在**：Tabbit `Extension State` 里有
  `fkebhmogekekphpcggaclfgpfmofhdjk.context_menus`，`string_uid=dlm-download`、`contexts=232`
  （link/image/video/audio）；UIA 真右键也列出了 `Download with dlm`，点它后宿主创建了新任务。
- **宿主收到了任务**：`%LOCALAPPDATA%\dlm\native-host\jobs` 里 20:44–20:50 有三份日志，内容都是
  `dlm 跑不起来：试探请求被服务器拒绝：HTTP 403 Forbidden`。
- **请求里没有 User-Agent**：本机抓头服务器的记录只有
  `range / accept-encoding / accept / referer / host`，**没有任何 UA**。
- **无 UA 就是 403 的来源**：同一个 ModelScope LFS 链接
  （`.../resolve/master/Unlimited-OCR-2.pdf`，1,515,878 B）：

  ```text
  curl -H "User-Agent:"        -> 403
  curl -A "dlm/0.1.0"          -> 206
  curl -A "Mozilla/5.0 ..."    -> 206
  ```

  即 CDN 只要求“有 UA”，`dlm/0.1.0` 这种自报家门的字符串即可，不需要冒充浏览器。

## 修复

- `src/consts.rs`：`pub const USER_AGENT: &str = concat!("dlm/", env!("CARGO_PKG_VERSION"));`
- `src/engine.rs::build_client` 与 `src/hls.rs::build_hls_client` 都加 `.user_agent(USER_AGENT)`；
  探测、分段、整份下载、HLS 共用这一形状。
- 回归针：`engine::tests::every_http_request_carries_the_dlm_user_agent`（本地 TcpListener 抓请求头）。

## 验证

- 真实 URL：`dlm --url .../Unlimited-OCR-2.pdf` ⇒ 退 0，落盘 **1,515,878 B**（修复前同链路 403）。
- 真实右键链路：本地起“无 UA 就 403”的站点，Tabbit 右键 → `Download with dlm`；
  服务端记录 `ua="dlm/0.1.0"`，落盘 `tabbit-file.bin` **4 B**。
- 四闸：`--lib` **308/0**（3.01 s；新增 1 针）· `--bins` **4/0** · `integration` **117/0**（65.33 s）
  · `clippy --all-targets -- -D warnings` **0**。
