# 0.7.5 打包与发布实测（2026-11-27）

用户指令：「打包并发布 然后清理之前的打包」。

## 一、打包

用仓库自带的脚本，没有手工拼：

```
powershell -File packaging\build-package.ps1 -Release 0.7.5 -Notes <本轮说明>
powershell -File packaging\build-mcp-package.ps1 -Release 0.7.5
```

脚本自己卡了三件事，都没被绕过：

- `-Release` 必须与 `src/gui/mod.rs` 的 `gui::RELEASE` 一致（不一致直接抛错）
- 扩展版本从 `browser/extension/manifest.json` 读，写进清单
- MCP 包单独打，打完会跑一次 `dlm-mcp.exe --version` 自检

产物：

| 文件 | 字节 | sha256 |
|---|---|---|
| `dlm-0.7.5-win-x64.zip` | 12,472,601 | `8d097cc9cce37a66cb662837b6e872b128565434cb315d28c77d4a7c452564b3` |
| `dlm-mcp-0.7.5-win-x64.zip` | 2,109,080 | `adc49ef646242e3c3aa62bec513a95a700be11b38b7573632ed1316e0b5b89fe` |

MCP 包自检输出：`Download Manager MCP 桥接 0.7.5（内核 0.1.0，接口 api 2）`。

## 二、包内容核对（发布前做的，不是发完才看）

| 检查 | 结果 |
|---|---|
| 包内 `browser/extension/manifest.json` 的 version | **0.2.17** |
| 包内 service worker 文件名 | `background-0.2.17.js` |
| `content.js` 含 `context-target`（右键认得按钮） | 是 |
| `content.js` / `background-0.2.17.js` 含 `show-batch-confirm`（批量先确认） | 是 |
| `background-0.2.17.js` 含 `info.srcUrl \|\| remembered.url` | 是 |
| 4 个 exe 与 `target\release` 的 sha256 | 逐个一致 |
| `dlm-gui.exe` 里含版本串 `0.7.5` | 是 |
| `dlm-gui.exe` 里含版本串 `0.7.4` | 否 |

最后两条是特意查的：版本号只写在 `gui::RELEASE` 常量里，如果哪天打包漏了重新编译，
包里就会是旧 exe —— 而这种事从文件名看不出来。

## 四、发布后验证（全部重新从网络取，不看本地）

1. **重新下载两个资产并重算 sha256**：

   ```
   dlm-0.7.5-win-x64.zip      12,472,601 字节  匹配 / sha 匹配
   dlm-mcp-0.7.5-win-x64.zip   2,109,080 字节  匹配 / sha 匹配
   ```

   服务端自己的 `digest` 字段也与上面两个 sha256 一致。

2. **`main` 分支的 `latest.json`**（更新器读的那份）：

   | 字段 | 值 |
   |---|---|
   | release | 0.7.5 |
   | core | 0.1.0 |
   | extension | 0.2.17 |
   | min_core | 0.1.0 |
   | size | 12,472,601 |
   | sha256 | 与本地 zip 一致 |
   | url | `.../releases/download/v0.7.5/dlm-0.7.5-win-x64.zip` |

   提交 `e222ec08`，blob `b83bbec7`。

3. **`raw.githubusercontent.com` 直读**：`release = 0.7.5 / extension = 0.2.17`。
   这次没有 CDN 延迟（0.7.4 那次刷了 4 次才更新，属正常范围）。
