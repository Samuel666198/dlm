## 一、选项面板：IDM 的 7 个标签页 vs dlm 的 3 组

IDM 那张图是「配置 Internet Download Manager」，顶部七个标签：
**常规 / 文件类型 / 保存至 / 下载 / 连接 / 代理服务器 / 声音事件**，
当前停在「常规」，里面是浏览器集成那一块。

dlm 的设置面板（`src/gui/app/settings_ui.rs`）只有三组：

| dlm 分组 | 项 | 对应 IDM |
|---|---|---|
| 下载 | 每个任务的连接数（1–32） | 连接 |
| 下载 | 同一服务器最大连接数（0–32，0=不限） | 连接 |
| 下载 | 全局限速 KiB/s（0=不限） | 连接 |
| 行为 | 监视剪贴板 | 常规 ·「监视剪贴板中的下载链接地址」 |
| 行为 | 完成后动作（留空 / open / run:exe） | 下载 · 完成后动作 |
| 界面 | 关闭窗口时收进托盘 | —（dlm 特有） |
| 界面 | 收进托盘时提示 | —（dlm 特有） |

### 逐项对照 IDM 常规页

| IDM 项 | dlm | 说明 |
|---|---|---|
| ☑ 系统启动时运行 IDM | **部分** | `install.ps1 -Autostart` / `dlm-gui --autostart-install` 写 HKCU Run 项，但**设置面板里没有开关**，只能靠命令行。而且 **E14 未解决**：自启会弹窗 |
| ☐ 监视剪贴板中的下载链接地址并自动开始下载 | **部分** | 有开关，但**不会自动开始下载**：`clipboard.rs` 命中后只 `eprintln!` 打一行，UI 提示条和自动入队都没接（源码注释自己写着「UI 侧的提示条在下一步接」） |
| ☐ 监视基于 IE 内核的浏览器（Maxthon、MSN 等）的点击事件 | **不做** | 需要浏览器内核钩子；dlm 走扩展，不做 IE 内核 |
| ☑ 使用高级浏览器集成 | **部分** | 扩展 + Native Messaging 已交付（B1/B2/B3a/B3b/B10），但**没有这个开关**：装了扩展就是全局接管，不能按站点/按浏览器关 |
| 「捕获以下浏览器的下载行为」复选框列表 | **不做（等价物不同）** | IDM 列的是 Safari/Doubao/Chrome/IE/Edge/Firefox/Opera —— 靠进程内注入实现。dlm 只有一个 MV3 扩展包（Chrome/Edge 同包），Firefox/Opera 未做（证据表 B1「已覆盖（部分）」） |
| 「添加浏览器…」 | **不做** | 同上，没有注入式接管就没有这个入口 |
| 「自定义暂停调用或强制调用 IDM 的快捷键」 | **无** | 没有任何全局热键实现 |
| 「自定义浏览器右键菜单中的 IDM 菜单项」 | **无** | 右键菜单是扩展里硬编码的一条「Download with dlm」（`background-0.2.11.js::installMenu`），用户不能改文案/增删项 |
| 「自定义浏览器中的 IDM 下载浮动条」 | **无** | 悬浮球的位置只能拖动+重置，颜色/尺寸/行为不可配 |

### 其余六个标签页

| IDM 标签 | dlm |
|---|---|
| 文件类型 | **无**（接管规则靠扩展的 `FILE_LINK_RE` 硬编码后缀表，用户改不了） |
| 保存至 | **部分**：`--out-dir` / 设置里的 `out_dir`，但设置面板里**没有这一项**，只能改 JSON 或用命令行；分类目录靠 `--category-dirs` |
| 下载 | **部分**：只有「完成后动作」一项（`open` / `run:`） |
| 连接 | **有**（连接数、每 host 上限、限速），但见下面的坑 |
| 代理服务器 | **无**。IDM 支持 HTTP/SOCKS 代理、PAC、认证；dlm 全程 `no_proxy()`（`host.rs::try_queue` 明确关掉代理），跟系统代理 |
| 声音事件 | **无** |

## 二、两个已确认「界面有、实际不生效」的坑

这两个比「缺功能」更糟 —— 用户改了设置以为生效，其实没有。

### 坑 1：`connections` / `max_speed` 没透传给子进程（已知欠账，这次确认了范围）

- `settings.rs` 里字段齐全，`settings_ui.rs` 里能改、能存盘。
- 但 `gui/mod.rs:167` 写死：`let per_host = 8usize; // 设置面板接进来后改成读设置（勘误 E5）`
- `gui/runner.rs::child_args` 构造 `dlm.exe` 参数时**只传** `--url / --out-dir / --out-name / --quiet / --referer / --on-complete / --max-bytes`，
  **没有 `--connections`，也没有 `--max-speed`**。
- 结果：设置里改成 16 连接、限速 1 MiB/s，实际仍跑 8 连接、不限速。

**修复很直接**：`child_args` 加两个参数，`gui/mod.rs` 的 `per_host` 从设置读。
代价小，但要补单测钉住「设置 → 子进程参数」这条链。

### 坑 2：剪贴板监视命中后什么都不做

`clipboard.rs:192`：

```rust
// 目前只把命中记到 stderr；UI 侧的提示条在下一步接。
eprintln!("dlm-gui: 剪贴板发现下载链接 {}", hit.url);
```

也就是说开了这个开关，复制一个 `.zip` 链接，**界面上没有任何反应**（只有 stderr 一行，
而发布版是 GUI 子进程，stderr 用户根本看不到）。IDM 那个勾选框写的是
「监视…**并自动开始下载**」，dlm 这边连提示都没有。

## 三、站点抓取（图 2）：完全没有，且是明确裁定不做

`grep` 全仓（`src` / `tests` / `browser` / `docs`）找 `抓取 / grabber / spider / crawl / sitemap`，
**没有任何实现代码**。唯一的命中是证据文档里的「不做」记录。

这不是遗漏，是**从第一天就写进裁定的**：

| 文档 | 原文 |
|---|---|
| `specs/2026-10-15-dlm-kernel-design.md:8` | 「v1 只做内核与 CLI。不做守护进程、不做浏览器扩展、不做 GUI、**不做站点抓取**」 |
| 同文件 `:141` | 「…**站点抓取与镜像**、…」列在明确不做的一侧 |
| `plans/2026-10-18-控制员代裁清单.md:56` | 「不做守护进程 / 浏览器扩展 / Native Messaging / **站点抓取** / GUI …」 |
| `specs/2026-11-09-native-shell-design.md:116-117` | 「**WebGrabber 镜像**/直播录制/DASH 合流」列为不做 |
| `specs/2026-11-10-native-shell-full-design.md:29` | 「**站点抓取**、FTP、拨号、DASH/DRM（recon P2）」 |
| `evidence/2026-10-21-idm能力对照表.md:84,97,139` | `D4` Grabber 缓存「不复刻」；`E3` WebGrabber 镜像「不做」；`P2-19`「不做；B3 仅非 DRM 直链/清单，单独立项」 |

图 2 那个「站点抓取」向导（抓取方案名 / 开始页面 / 方案模板 / 使用授权 / 高级）
对应的是 IDM 的 WebGrabber：按规则爬一个站点、把整站资源镜像下来、支持登录态和项目模板。
它跟 dlm 现在的能力**不是一个量级**：

| 维度 | dlm 现状 | 站点抓取需要 |
|---|---|---|
| 抓取范围 | 单个 URL，或扩展在当前页嗅探到的链接列表 | 整站遍历、深度/范围限制、sitemap、robots |
| 链接发现 | 扩展看当前 DOM 的 `<a href>` + 网络嗅探 | 爬虫队列 + 去重 + 优先级 |
| 登录态 | `--cookie` / `--user` / `--password` 一次性传入 | 持久会话、登录流程脚本、表单提交 |
| 落盘结构 | 平铺到 `--out-dir` | 保留站点目录树、改写链接、相对路径重写 |
| 断点 | 单文件断点 | 整项目断点（哪些页面抓过） |
| 界面 | 一个新建任务弹窗 | 向导、方案模板、项目列表、预览 |

**我的判断：这是独立产品级功能，不该混在「还原 IDM 选项」里做。**
如果真要做，应该单独立项（一份 spec + 一份 plan），先只做「同域、固定深度、
只抓静态资源」的最小版本，不要一上来对标 IDM 的完整 WebGrabber。

## 四、为什么没有真点开窗口

用户说「你可以自己点开看看」。我没有做，原因：

1. **这台机器上有一个 `dlm-native-host`（PID 33660）正连着你的浏览器**，
   而 `%LOCALAPPDATA%\dlm\bin` 里装的是**旧包**的二进制。点开窗口看到的是旧版本，
   拿它当证据会得出错误结论 —— 这正是这个项目栽过三次的坑（见
   `2026-11-11-extension-ball-fixes.md`：拿合成输入/旧状态当真实情况）。
2. 设置面板的每一项，**代码里能直接读出「有没有、存哪、传没传下去」**，
   比点开看界面更准：界面只能证明「控件存在」，读代码才能证明「值有没有到子进程」。
   坑 1 和坑 2 就是靠读代码发现的，点界面看不出来。
3. 真要实测，得先重装新包、关掉旧宿主，再逐项点 —— 那是**验证阶段**的事，
   不该混在「清点功能」这一步。

如果之后要实测，我会按这个顺序：装新包 → 关旧宿主 → 改设置 → 用 `--connections`
验证子进程命令行（`Get-CimInstance Win32_Process` 读实际 argv）→ 再点界面。

## 五、给下一版的优先级建议

用户说「这些作为后续的更新方向」。我按「性价比 × 用户可感知」排：

| 优先级 | 项 | 理由 | 代价 |
|---|---|---|---|
| **P0** | 修坑 1：`connections`/`max_speed` 透传 | 设置界面在说谎，用户改了不生效 | 小，2 个参数 + 1 处读设置 + 单测 |
| **P0** | 修坑 2：剪贴板命中要有 UI 反应 | 同上，开关形同虚设 | 小，加一条提示条 |
| **P1** | E17 粘贴（已定位，一行 feature） | 基础交互坏 | 极小 |
| **P1** | E16 暂停后没有「继续」 | 已定位，用户明确要 | 中 |
| **P2** | 设置面板补「保存目录」「开机自启」开关 | 这两项现在只能命令行改，普通用户够不到 | 小 |
| **P2** | 右键菜单文案可配 / 悬浮球可配 | IDM 有，用户能感知 | 小 |
| **P3** | 文件类型白名单可配 | 现在是硬编码正则，高级用户会想要 | 中（要跟扩展静态检查联动） |
| **不做** | 站点抓取 / WebGrabber | 产品级功能，单独立项，不在选项面板范畴 | 极大 |
| **不做** | IE 内核监视、全局热键、代理服务器、声音事件 | 与 dlm 架构不符或价值低 | — |

**建议**：下一版做 P0 两项 + P1 两项（坑1、坑2、E17、E16）。
这四项都是「已定位、代价小、用户直接可感知」，适合一个版本收口。
设置面板补齐（P2）放再下一个版本。
