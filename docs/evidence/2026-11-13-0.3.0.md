# 0.3.0 交付记录（2026-11-13）

## 一句话

浏览器里「该下的都进 dlm」：浏览器自己发起的下载（JS 触发 / 302 / iframe / 附件）现在也能接管，
靠的是「先让 dlm 建好任务、再取消浏览器下载」的两段式，而不是驱动层的抢先。

## 做了什么

### 协议（Rust）

- `download` 请求新增可选 `request_id`；`accepted` 在 **queue 与 direct 两条路径**都原样回显。
  没有它，并发接管时无法把回执对应到具体那次下载。
- 测试：`host::tests::download_spawns_the_configured_program_and_returns_a_job` 断言回显；
  未带 `request_id` 的调用方保持原行为（字段为 null）。

### 扩展接管（0.2.14）

- 新文件 `takeover.js`：纯判定（无 `chrome.*` 依赖，node 可直接测）
  - 扩展名白名单（默认 zip/7z/rar/gz/tar/iso/exe/msi/dmg/pkg/mp4/mkv/avi/mov/webm/flac/mp3/wav/pdf/epub/apk）
  - MIME 白名单：`application/zip|7z|rar|gzip|iso|apk|msdownload|msi|pdf|epub` + `video/*` + `audio/*`
  - 站点黑名单（与 A3 共用 `siteBlock`）
  - 最小体积、必须 `in_progress` 且 `bytesReceived === 0`
- `background-0.2.14.js`：`downloads.onCreated` → 生成 `request_id` → 发 `download`；
  收到匹配 `accepted` 才 `chrome.downloads.cancel()`；**2 秒无回执放弃并记 `no-ack`**；
  文件名直接取浏览器已落定的 `item.filename`（`Content-Disposition` 由浏览器解析，扩展不重复实现）。
- `options.html/js`：接管开关（默认关）、扩展名白名单、最小体积、站点黑名单。
- `manifest.json`：新增 `downloads` 权限。

## 验收步骤（人工）

1. 安装 0.3.0（先退托盘），`edge://extensions` / `chrome://extensions` 点「重新加载」
2. 扩展「选项」出现「接管浏览器下载」区块
3. 开接管 → 点 zip 附件：浏览器下载消失、dlm 出现任务
4. **反向**：退出 dlm 再点 zip → 浏览器下载必须保留（两段式保护生效）
