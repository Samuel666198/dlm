用户要求「正式的 Windows 安装包，不要压缩包」。本文件记下**做了什么、怎么验的、踩了什么坑**。

## 契约

| 项 | 值 | 为什么 |
|---|---|---|
| AppId | `{A7C4F1D2-3B9E-4C5A-9D31-7C2E8F10B6A4}` | 一旦定下不能改：它是「同一个软件」的身份证。改了会在「应用和功能」里出现两条 dlm，且新包不会覆盖老包 |
| 安装位置 | `%LOCALAPPDATA%\dlm\bin` | **当前用户安装，全程不要管理员**。理由是自动更新：`dlm-updater.exe` 直接替换安装目录里的 exe，它不提权；装到 Program Files 就会变成「装得上、更新不了」 |
| 登记 | `HKCU\...\Chrome\NativeMessagingHosts\com.dlm.host`、`HKCU\...\Edge\...`，值指向 `{app}\com.dlm.host.json` | 清单里要写 exe 的绝对路径，所以清单在 `[Code]` 里按实际 `{app}` 生成；`uninsdeletekey` 保证卸载清干净 |
| 扩展 | `%LOCALAPPDATA%\dlm\extension`（0.2.12） | 不上商店，用户仍需在 `chrome://extensions` 点一次「加载已解压」/「重新加载」 |
| 快捷方式 | 开始菜单 `dlm`；桌面可选；开机自启可选（两个 `[Tasks]`，默认都不勾） | 与 `install.ps1` 写的是同一个 Run 值（`dlm-gui --autostart`） |
| 卸载 | 删 exe、扩展目录、native host 清单与注册表；**不动** `queue.json` / `settings.json` / 下载文件 | 卸载不该顺手删用户的数据 |

## 怎么验的（一次性探针，跑完已删）

把 setup 静默装到**临时目录**（`/DIR` 覆盖）→ 逐项断言 → 静默卸载 → 断言清干净 →
把注册表与扩展目录还原成用户原来的样子。**20 项全 PASS**：

```
setup exit 0 · 四个 exe 都在（含 dlm-updater.exe）· 扩展 0.2.12 落盘
native host 清单写出来且能被 JSON 解析、path 指向安装目录、allowed_origins 是那个扩展 ID
Chrome/Edge 两处注册表都指向该清单 · 开始菜单快捷方式在 · 卸载器在
卸载 exit 0 · 安装目录没了 · 快捷方式没了 · 两处注册表 key 没了 · 扩展目录没了
还原后：注册表回到 C:\Users\ROG\AppData\Local\dlm\native-host\com.dlm.host.json
       扩展 0.2.12 · 快捷方式已重建
```

> 探针有个**副作用**要记住：卸载会删掉 `%LOCALAPPDATA%\dlm\extension` 和开始菜单快捷方式
> —— 所以探针里必须先整份备份扩展目录，`finally` 里还原；快捷方式要按原样子重建。
> 第一次跑完忘了这一步，用户的快捷方式被删了（当场用 `WScript.Shell` 重建）。

## 三个当场撞出来的坑

1. **`param()` 必须是脚本第一条语句**（注释之外）。我把 `$ErrorActionPreference` 写在前面，
   PS 直接报 `The assignment expression is not valid`。
2. **`.ps1` 里 `2>&1` + `$ErrorActionPreference='Stop'` 会把原生命令的 stderr 当终止错误**
   （`.NativeCommandError`）—— `cargo` 的输出全走 stderr，于是构建明明成功却中断。
   修法：调用那一行前后临时把 EAP 放宽成 `Continue`，拿 `$LASTEXITCODE` 判断成败。
3. **PS 5.1 读文件默认按本地代码页**：`Get-Content -Raw` 读带中文的 `manifest.json`
   ⇒ 乱码 ⇒ `ConvertFrom-Json` 抛「无效的 JSON 原语」。必须显式 `-Encoding UTF8`。
   同一族还有写：`Set-Content -Encoding UTF8` 在 5.1 下会写 **BOM**，而
   `serde_json::from_slice` 见到 BOM 直接报 `expected value` —— 更新检查会整条挂掉。
   所以 `latest.json` 改成 `[System.IO.File]::WriteAllText(..., UTF8Encoding($false))`。

## 顺手修正的两处打包逻辑

- **文件名按发行版版本走**（`dlm-<release>-win-x64*`），不按内核版本。用内核版本命名的话，
  「内核没变、只发了发行版」的包会覆盖上一个包的同名文件 —— 而那个文件可能已经发布了。
- **`-Release` 缺省值取 `gui::RELEASE`**，不再取 Cargo 的 `version`：用户感知的是发行版，
  两者本来就允许不同（本次就是 内核 0.1.0 / 发行版 0.1.1）。

## 发版顺序（含安装包）

```powershell
# 1. 改 src\gui\mod.rs 的 gui::RELEASE（本次 = 0.1.1），跑门禁
powershell -NoProfile -ExecutionPolicy Bypass -File .\gates.ps1
# 2. 一次打出 zip + latest.json + setup.exe
powershell -NoProfile -ExecutionPolicy Bypass -File .\packaging\build-installer.ps1 -Notes "这次改了什么"
# 3. 建 Release v<release>，把 zip 和 setup.exe 都传上去
# 4. 用 target\package\latest.json 覆盖 main 分支那份，推 main
```

**顺序不能反**：先确认资产上传成功（匿名 GET 200），再改 `latest.json` ——
否则用户点「立即更新」会去下一个还不存在的地址。

# 图标与「打开时附带终端」的修复（同日补做）

## 1. 图标

**症状**：程序在资源管理器、开始菜单、任务栏固定项里都是白底默认图标。

**为什么窗口里有图标、exe 却没有**：窗口/托盘图标是**运行时画**的
（`gui::window_icon()`、`gui::app::tray::make_icon()`，都画了个圆角方块 + 白色下箭头），
那只影响程序自己画出来的窗口；**文件图标**来自 exe 的**资源段**，而原来一个资源段都没有。

**做法**（不引入新依赖）：
- `assets\icon\dlm.ico`（16/24/32/48/64/128/256）+ `dlm-256.png`，几何与 Rust 里画的一致
  （圆角半径 7/32、主色 `#C06340`、竖杆宽 3/32 从 9/32 到 18/32、三角头 17/32 起半宽 6/32）
- `build.rs` 生成一份 `.rc`（图标 + VERSIONINFO），调 Windows SDK 的 `rc.exe` 编成 `.res`，
  用 `cargo:rustc-link-arg-bins` 交给链接器 —— **只给 bin**，测试 exe 不塞图标
- 找不到 `rc.exe`（没装 Windows SDK）时只打一条 warning，**不影响编译**：
  没图标总比构建不了强
- 安装包自己也带上了图标（`SetupIconFile`）

## 2. 打开时冒出一个黑色终端

**根因**：Rust 默认把 bin 编成**控制台**子系统，Windows 于是先分配一个控制台窗口再跑 GUI。
用户看到的是「打开软件附带出现一个终端」，关掉那个窗口还会把程序一起带走。

**做法**：
- `src\bin\dlm-gui.rs` 加 `#![cfg_attr(all(windows, not(test)), windows_subsystem = "windows")]`
  （与 `dlm-native-host` 同一写法）。`dlm.exe`（CLI）**必须保持控制台**，否则命令行下看不到输出。
- `dlm-updater.exe` 保持控制台（要能手动跑、看输出），但 `gui::spawn_updater` 起它时加
  `CREATE_NO_WINDOW`：GUI 自己没控制台，控制台子进程会被**新分配**一个窗口，更新时会闪黑框。
- 副作用要接住：没有控制台以后，双击启动失败就是「什么也没发生」。所以补了
  `report_fatal()` —— GUI 模式下用 `MessageBoxW` 弹一句；`--headless` 时只走 stderr
  （集成测试都用 `--headless`，弹框会把用例挂死）。

## 5. 一处仍然诚实的欠账

`rc.exe` 是从本机的 Windows Kits 找到的（`10.0.26100.0\x64\rc.exe`）。换一台**没装 Windows SDK**
的机器打 release 包，exe 会没有图标（只打 warning）。要彻底摆脱这个依赖，得换成
`embed-resource` 之类的 build-dependency，或者把 `.res` 预先编好提交进仓库 —— 现在没做。
