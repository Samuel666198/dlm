# 右键菜单只在右栏打开时触发：定位与修复（2026-11-27 报 / 2026-11-28 定案）

## 现象

用户：「右键菜单只会在右侧栏打开时触发」。前两轮实测都复现不了 ——
因为观测手段本身不成立。

## 三次观测，前两次都错

1. **看 `context_menu_for`**：它只记"本帧菜单有没有画出来"。
   右键当帧当然有，所以永远显示"正常"。
2. **想查 `Memory::any_popup_open()`**：egui 0.37 里它是私有的。
3. **`Memory::areas().visible_layer_ids().len()`**：菜单是独立图层，开着就多一层。
   这个才看得见真相。

## 真相（修前）

```
drawer_open=false: 点前 1 / 点当帧 2 / 次帧 1 / 再一帧 1   ← 一帧就没了
drawer_open=true : 点前 1 / 点当帧 2 / 次帧 2 / 再一帧 2   ← 一直活着
```

**根因**：行里的右键分支顺手设了 `self.selected = Some(id)` ⇒ 右栏在**同一帧**张开
⇒ 列表变窄（908 → 578）⇒ 刚弹出来的菜单失去锚点，下一帧被关掉。
右栏本来就开着时不会重排，所以看着"只有右栏开着才灵"。

## 修法

右键只设 `context_target`（**只做高亮**），不碰 `selected`：

- `App::context_target: Option<String>` 新字段
- 行高亮 = `selected || context_target == 本行`
- 高亮**只活到菜单关掉**：`list()` 开头清 `context_menu_for`，末尾若它仍是空 ⇒ 清 `context_target`
- 菜单里的动作本来就都用 `task`，不依赖 `selected`，所以去掉它没有副作用

## 修后

```
drawer_open=false: 点前 1 / 点当帧 2 / 次帧 2 / 再一帧 2
drawer_open=true : 点前 1 / 点当帧 2 / 次帧 2 / 再一帧 2
```

用例 `the_row_menu_survives_a_right_click_with_the_drawer_closed` 钉三件事：
两帧后层数一致、右键**不打开**右栏、`context_target` 指向被点的行。
变异（把 `selected` 那行加回去）⇒ 立刻红，且打印出 `1 → 2 → 1` 的旧形态。
