# 表头与列「错位」：其实是列内文字起点差 19pt（2026-11-28 定案）

## 现象

用户 图 2：表头「文件名」与下面那列文件名对不齐，像是列错位。

## 实测：列坐标完全一致

```
drawer_open=false: 表头 左184.0 名218.0 大小638.0 状态1016.0 / 行 左184.0 名218.0 大小638.0 状态1016.0
drawer_open=true : 表头 左184.0 名512.0 大小686.0 状态686.0 / 行 左184.0 名512.0 大小686.0 状态686.0
```

表头与行用的是同一个 `columns(rect)`，矩形也同源 —— **列本身没错位**。
（前一轮只比了宽度，那不够：`columns` 按 `rect.left()/right()` 定位，
宽度一样而原点不同照样会整体错位。这一轮比的是四个实数坐标。）

## 真凶：列内文字的起点

行里的文件名前面有**类型图标**（`NAME_ICON + NAME_GAP = 19pt`），
文字因此右移；而表头「文件名」还画在列左缘 —— 于是永远差 19pt。

变异（把标签改回画在列左缘）打出来的正是这个数：

```
「文件名」文字起点不一致：表头 218.0 / 行 237.0
```

## 修法

`NAME_ICON / NAME_GAP / NAME_TEXT_INSET` 提成常量，行与表头**共用同一份**；
表头标签画在 `name_rect.left() + NAME_TEXT_INSET`。

## 又踩了一个假绿

第一版探针 `thead_name_x` 是**自己又算了一遍** `列左缘 + INSET`，所以变异打不红 ——
用例测的是探针，不是代码。改成"标签的 x 只算一次，同一个值既拿去画也记进探针"之后
变异才红。

## 证据

修后真界面截图（1122×732，三条长名任务）：表头「文件名」与行内文件名左缘同为 x≈237。
