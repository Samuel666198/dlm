# 网页不是文件：默认拒绝（2026-11-27）

## 为什么做这一步

用户原话：「现在使用dlm下载还是有问题」，并贴了截图：`BV1atse6EEfx`（B 站视频页 URL）
被当成普通文件下回来了。核过原因：服务器对这个地址回的是 `Content-Type: text/html`，
而内核**从来没看过这个头** —— 于是 76 字节的网页被当成"视频"落盘，用户打开才发现打不开。

这也是 F/G「视频下载」的第一半：先别下错，再接 yt-dlp。

## 改了什么

1. `consts::FLAG_ALLOW_HTML`（1<<4）+ CLI `--allow-html`
2. `probe::looks_like_html(headers, name)`：`Content-Type` 是 html 系
   **且**落点名字不像网页（`.html/.htm/.xhtml/.mhtml/.shtml` 时不拦 —— 那是用户真要下的）
3. `probe::run_with_limiter` 在状态码检查之后拦一道，消息里给出退路 `--allow-html`

## 证据（真 CLI，本机裸 HTTP 服务器回 text/html）

```
$ dlm --url http://127.0.0.1:47802/BV1atse6EEfx --out-dir target\html-check
dlm 跑不起来：这个地址返回的是网页（text/html），不是文件 —— 多半是视频页、BV 号或分享链接。
如果确实要下载这个网页，请加 --allow-html
退出码=1                      ← 落点目录里什么都没写

$ dlm --url http://127.0.0.1:47802/BV1atse6EEfx --out-dir target\html-check --allow-html
下载已完成  目标：…\BV1atse6EEfx  全长 76 B，落盘 76 B，归属已定 76 B
退出码=0                      ← 目录里 76 字节的文件
```

## 用例与变异

- `probe::tests::an_html_response_is_not_treated_as_a_file`：7 种头/名字组合
- `tests/integration.rs::a_web_page_is_refused_unless_html_is_allowed`：
  自带裸 TCP 服务器，先验拒绝（消息里必须同时有「网页」和 `--allow-html`），
  再验 `--allow-html` 之后长度按服务器报的算
- 变异：把拦截条件换成 `if false` ⇒ 用例红，且错误原文里能看到那 58 字节
  `<html>…` 被当成 prelude 收下了 —— 正是用户踩的那个坑

门禁 10/10：lib 608 / integration 128。
