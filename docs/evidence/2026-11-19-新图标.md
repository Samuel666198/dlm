# 2026-11-19 换程序图标

用户给了一张新图标（陶土橙 squircle + 三支箭汇成一支，奶白色），要求替换程序图标。

## 一个图标，四个落点

| 产物 | 谁用 | 大小 |
|---|---|---|
| `assets/icon/dlm.ico` | exe 资源段（`build.rs` 编进 .res）+ 安装包 `SetupIconFile` | 16/24/32/48/64/128/256 共 7 档 |
| `assets/icon/dlm-64.rgba` | egui 窗口图标（`gui::window_icon`） | 16384 字节 |
| `assets/icon/dlm-32.rgba` | 托盘图标（`gui::app::tray::make_icon`） | 4096 字节 |
| `assets/icon/dlm-256.png` | 文档/发布页展示，不参与运行时 | 256×256 |

`assets/icon/source/dlm-icon.webp` 是源图（1254×1254），四个落点都由
`packaging/make-icon.py` 从它烘出来 —— 手改任何一个二进制都会让它们各走各的。

## 换图标为什么要动代码

原来窗口图标和托盘图标是**手写循环画的**（32×32 圆角方块 + 白色单箭头），
和 `.ico` 里那张是两套画。换了新图标后如果只改 `.ico`，任务栏里是三支箭、
托盘里还是旧单箭头 —— 同一个程序两个样子。所以两处都改成读烘好的像素。

为什么烘裸 RGBA 而不是运行时解 PNG：项目没引入图片解码依赖（`Cargo.lock` 里连
`png` 都没有）。要么加一个 crate，要么把像素放进仓库 —— 选后者，与 `updater`
直接调 `powershell` 解压是同一个取舍。

## 源图处理（脚本做的三件事）

1. 按 alpha ≥ 200 求 squircle 主体 bbox（917×914），扩成正方形并留 2% 内边距
2. **去掉外围那层极淡的白色光晕**：源图 alpha 16–63 的像素占 50% 面积。那层光晕
   在浅色界面上看不出来，但在深色任务栏上会变成一层灰雾
3. 按 LANCZOS 缩到各档尺寸

## 实测

- exe 内嵌图标：从 `target\debug\dlm-gui.exe` 用 `ExtractAssociatedIcon` 抽出来，
  确认是三支箭的新图（见图）
- 窗口标题栏：真实窗口截图，标题栏左侧已是新图标
- 任务栏按钮：真实截图，陶土橙 squircle 三支箭
- 各尺寸清晰度：16 / 24 / 32 / 48 / 64 对照表（下排为最近邻放大 4×）。
  16px 下三支箭会并在一起，但仍能读作"向下的箭头"；24px 起清晰

## 回归用例（两条，都做过变异验证）

- `tray::tests::the_tray_icon_pixels_are_the_baked_asset`
- `gui::tests::the_window_icon_comes_from_the_same_baked_asset`

判据是**三支箭的结构**，不是"有个图标"：
左上 / 右上各要有奶白像素（第二、第三支箭），而两者之间的空隙必须是背景色。

只断言"中心是白色"是没用的 —— 旧版单箭头中心也是白的，那种断言新旧都能过。
变异验证：用 Pillow 生成"旧版单箭头"形态写进 `.rgba`，两条都变红，报出
`左上应是第二支箭的奶白色，实际 [192, 99, 64, 255]`（正是旧版的强调色）。

## 重新生成

    python packaging/make-icon.py
    python packaging/make-icon.py --source assets/icon/source/dlm-icon.webp

脚本自带两条自检：字节数必须等于 `4*w*h`；裸像素不许整张全透明。
