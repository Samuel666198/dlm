# 能力对照表 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 `idm-recon/docs/50-idm-capability-spec.md` 的每条能力对到 dlm 现状，产出一张四档对照表，给 A/B/C 路线排序提供证据。

**Architecture:** 只写文档，不改产品代码。以 50 号规格的 A/B/C/D/E 行为骨架逐行填 dlm 现状、判据强度、归属；再用 §二 P0/P1/P2 与 §三 O 洞做交叉核对。所有"已覆盖"必须能 `grep` 到真用例；所有"未取证"必须点名缺哪份证据。

**Tech Stack:** Markdown、ripgrep、`cargo test`/`cargo clippy`。

**Spec:** [`../../../../idm-recon/docs/50-idm-capability-spec.md`](../../../../idm-recon/docs/50-idm-capability-spec.md)（能力源）、[`./2026-10-21-下一任交接-HANDOFF.md`](./2026-10-21-下一任交接-HANDOFF.md)（已裁定与硬纪律）、[`./2026-10-21-三路路线图.md`](./2026-10-21-三路路线图.md)（本阶段的上游）。

## Global Constraints

- 四闸是 floor：`--lib`／`--bins`／`--test integration`／`clippy --all-targets -D warnings`，只许增、不许删、不许改判据方向。
- 只改文档；不碰 `src/`、`tests/`、`Cargo.toml`、`Cargo.lock`。
- 不推送；不 `checkout`/`reset`/`stash`。
- 不碰交接稿 §3 的十一档裁定；表里遇到它们一律标"已裁定不做"并给编号。
- 文档引用代码用**符号名**，不用行号；点名的用例先 `grep` 到 `fn <name>` 再写。
- 不把"实现有、无直接针"写成"已覆盖"；判据强度必须单独列。
- 状态词汇只有四档：**已覆盖**／**未取证**／**本机可验**／**不做或不复刻**。每档下面再标判据强度：活体针／单元针／仅有实现／无。
- 面向用户的说明用中文；命令、路径、用例名保持原文。
- Git Bash 下复量斜杠参数用 `MSYS2_ARG_CONV_EXCL='*'`；退出码单独取，不接在管道后面。

- [ ] **Step 2: 填 A1–A19**

逐行读 50 号规格 §一 A 表，把每行压成一句能力，填 dlm 现状。判定规则：

- 同一机制在 dlm 有实现且有测试 ⇒ `已覆盖`，判据写用例名；用例名必须先 `grep -rn "fn <name>" src tests` 命中。

- 明确不复刻的实现细节 ⇒ `不复刻`，理由指向 README/spec。
- 需要先补 IDM 取证 ⇒ `未取证`，写 `O-x` 或 `Q-B1/B2`。

A 表必须覆盖 `A1`–`A19` 共 19 行，不许合并行号。
