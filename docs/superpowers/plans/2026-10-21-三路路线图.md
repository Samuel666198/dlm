## 2. A 路线｜引擎侧

### A1 `If-Range` 条件续传（S/M）

**状态**：已交付（2026-10-21，R17）。

- **目标**：续传请求带验证器；对端 `206` ⇒ 继续，`200` ⇒ 从头重来。
- **必须裁清**：ETag 与 Last-Modified 谁优先；`--ignore-mtime` 只豁免 Last-Modified 那一步；`If-Range` 与现有"先自己比验证器"两道判据的先后。
- **交付**：断点里存"上一轮用的是哪种验证器"；`fetch`/`probe` 带上头；harness 能演两种响应；spec 新增一条勘误。
- **验收**：匹配续传、不匹配重来两臂；旧续传判据不回归；四闸；真公网复验一次。

### A2 全任务共享速率上限（M）

**状态**：已交付（2026-10-21，R18）。

- **目标**：`--max-speed` 对所有连接**合计**生效；`0`/缺省＝不限。
- **范围**：只做速率上限。IDM 的"配额到量暂停、择时恢复"跨到 A3（计划任务），不在本阶段冒充做完。
- **交付**：令牌桶用注入时钟做确定性测试，**禁墙钟判据**；进度行速率不回归。
- **验收**：多连接聚合速率、边界档（刚好等于上限、低于最低速率）、四闸。

### A3 完成后动作＋计划任务（M）

**状态**：A3a + A3b shutdown 已交付（R19/R20）；计划任务移到 C1；阻止休眠不做。

- **顺序**：先做完成后动作（运行程序／打开落点／关机），再做计划任务。
- **硬边界**：动作失败不许掩盖下载结果；关机必须显式开关＋延迟；测试只用 dry-run/替身，**不在测试里执行真关机**。
- **计划任务**：在 spec 里裁"进程内等到点"还是"生成系统计划任务"，不默认引入守护进程。
- **验收**：成功／失败／被拒绝三臂；四闸；README 安全边界。

### A4 劈分策略 v2 压 dup（L）

**状态**：已交付（2026-10-21，R21；48 MiB/8 worker 全速 dup 从 17.2% 降到 0.63%）。

- **目标**：把实测 12.8%–20.8% 的残余重复压到"每笔 ≤ 一块"。
- **性质**：改 spec §2.1 劈分规则，是 **v2 设计变更**，不是修 v1 bug；独立 spec＋plan。
- **交付**：新纯状态机规则＋旧规则对照量具（48 MiB 全速／限速／续传三档）。
- **验收**：dup 实测下降且总时长不显著退化；旧判据一条不许放宽；四闸。

### A5 IDM 断点格式兼容（XL/不确定，默认不做）

- 先取证 IDM 把段表存在哪种文件、什么编码；取证前不写代码。
- 除非你明确要"接续 IDM 未完成任务"，否则不排进主线。

## 3. B 路线｜浏览器/系统集成

### B0 取证 Q-B1/B2（S/M，只读）

- **目标**：量 Native Messaging 的注册/manifest 位置、消息帧、宿主路径、环回端口、握手、版本与来源校验。
- **产物**：写 dlm 的 `docs/evidence/`，**不写 `idm-recon`**。
- **验收**：每条结论带实测命令/日志；拿不到的标"未取证"。
- **前置**：你点头"只读复测"（本机跑 IDM＋浏览器观察）。

### B1 Native Messaging 最小闭环（M/L）

- **目标**：`dlm-native-host` ＋ 最小扩展：ping/pong、版本回执、扩展 ID 白名单、消息大小上限。
- **约束**：不新增 crate（JSON 已有）；宿主不执行任意命令。
- **验收**：真 Chrome/Edge 往返一次，日志为证；四闸。

### B2 浏览器下载接管（L）

- **目标**：右键/拦截下载 → 宿主 → dlm，带 Cookie/Referer；失败回执。
- **口径更新**：v1 说"Cookie 是第二类凭据"；跨进程后要重写这条边界，Cookie 不进日志。
- **依赖**：不依赖 C1；先用"每次下载一个进程"接上，C1 再把入口换成队列，协议不变。
- **验收**：端到端真浏览器下载；四闸；Cookie 不落日志。

### B3 非 DRM 媒体嗅探（XL，默认单独立项）

- **目标**：HLS/DASH/直链识别与下载。
- **前置**：B2；可能要 ffmpeg 或新依赖，和 6 crate 约束冲突。
- **明确不做**：DRM。建议单独立项，不塞进 B 的主线。

## 4. C 路线｜产品层

### C0 GUI 形态与依赖裁定（S，决策）

- **四选一**：egui/eframe（纯 Rust、依赖多）／Tauri（webview、构建重）／Win32（windows crate）／本地 Web UI（自写 HTTP、零新 crate 但工作量大）。
- **同时裁**："6 个直接依赖"的上限是否解除。
- **产物**：决策记录＋`cargo tree`/`cargo metadata` 实测依赖数，不凭猜。

### C1 多任务队列与持久化（L，无 GUI）

- **目标**：多任务排队、并发上限、暂停/继续/取消、分类的数据模型；先用 CLI 操作。
- **计划任务的落点（A3b 移入）**：队列项带起始时间/时间窗；仍不默认引入守护进程，先裁"常驻服务"还是"系统计划任务"。
- **兼容**：旧单任务断点必须可读。
- **验收**：排队／并发／恢复三组行为；四闸。

### C2 GUI 只读壳（L）

- **目标**：任务列表、进度、详情、打开目录；先只读不做编辑。
- **验收**：逻辑层四闸；**UI 必须真人走查**（截图/录屏），不能拿四闸绿冒充 UI 绿。

### C3 GUI 交互＋分类规则＋更新检查（L/XL）

- **目标**：新建/编辑/暂停/删除、分类规则、完成后动作、更新检查。
- **边界**：更新检查要访问外网，实现前单独点头。
- **验收**：真人走查；四闸；外网动作的必要性写清。

## 5. 执行纪律（每阶段都吃）

- 新功能先 spec → plan → 实现；每阶段四闸为 floor，只许增不许删、不许改判据方向。
- 报告先写、提交第二；引用代码用符号名；点名用例先 `grep`。
- 不碰交接稿 §3 那十一档裁定；不 `checkout`/`reset`/`stash`；不 push。
- 用户"全部授权"覆盖路线推进；**`git push`／真删／对外动作仍单独点头**；关机类真动作不在测试里执行；`idm-recon` 不写。
- 四闸只覆盖 Rust；B 的扩展代码和 C 的 GUI **不在四闸覆盖内**，另立真浏览器/真人验收，并如实标注"自动化没覆盖到"。
- v1 的"不做 GUI/浏览器扩展"是**版本边界**，不是 bug；各路线立项时把 README 改写成"v1 不做，v2 路线 X 做"。
