# dlm v2.1 更新计划：产品手感（2026-11-07）

**背景**：内核与浏览器链路已完成（311/4/117 四闸绿，扩展 0.2.7 悬浮球已交付）。
与 IDM 逐条对照后，剩下的差距集中在**产品手感**，不是下载能力：
失败任务要人盯着点“继续”、下载完找不到文件、每次开机要手动开 GUI。

**范围**：只做三件高频事 + 一批 UI 收尾。**不碰**内核调度、不破“6 个直接依赖”上限、不引入新进程模型。

**原则**：每条都先有判据再改代码；数字写 floor 不写 exact；行为变更必须同时改 README 与状态账。

## P1 队列失败自动重试

### 目标

任务以退出码 1 结束后，队列自动重排并续传，不需要人点“继续”。上限与间隔可配，可关闭。

### 为什么是退出码 1

`dlm` 的退出档是契约（README「退出码」节）：

| 码 | 含义 | 重试 |
|---|---|---|
| 0 | 下完 | 不适用 |
| 1 | 跑到结论但没下完（退避到顶、对端掐断等） | **重试** |
| 2 | 参数错 | **不重试**（重试必然同样失败） |
| 3 | `--max-bytes` 到量 | **不重试**（等下一个配额窗口，已有逻辑） |

队列**从不**给子进程传 `--sha256`，所以不存在“校验不符重试”这种无意义重跑。

### 改动面

| 文件 | 改动 |
|---|---|
| `src/queue.rs` | `Task` 增 `attempts: u32`（`#[serde(default)]`）；增 `retry_backoff(attempts) -> Option<u64>` 纯函数（0→30 s，1→120 s，≥2→`None`） |
| `src/gui.rs` | 子进程退出分支：`Some(1)` 且 `retry_backoff` 给得出间隔 ⇒ `status = Queued`、`hold_until = now + backoff`、`attempts += 1`；否则 `Failed` |
| `src/gui.rs` | `GuiConfig` 增 `max_task_retries: u32`，`--max-task-retries <N>`（默认 2，0 = 关闭） |
| `src/ui.html` | 任务行显示“重试 1/2”；详情页显示剩余等待秒数 |
| `README.md` | 「队列」节补自动重试口径与上限；已知限制补“404 之类永久错误也会重试满次数” |

### 判据

- `retry_backoff` 纯函数表：0/1/2/3 四档，越界给 `None`。
- 队列级：写一个假 `dlm`（`tests/harness` 里已有这类替身）退出 1 两次、第三次 0 ⇒ 任务最终 `done`，`attempts == 2`。
- 反臂：退出 2 与退出 3 各一条 —— 必须**不**进入重试（前者 `Failed`，后者 `Queued` 且 `attempts == 0`）。
- 反臂：`--max-task-retries 0` ⇒ 退出 1 直接 `Failed`。

### 已知代价（照实写进文档）

- 对端返回 404/403 这类**永久**失败也是退出 1，会白重试满次数（默认 2 次，最多多花两轮探测流量）。
  要区分得让 `dlm` 新增退出档，那是契约变更，本轮不做。
- 重试是**续传**不是重下；断点在，重复流量按 `--max-bytes` 那套账走。

## P2 打开文件 / 打开所在文件夹

### 目标

完成任务行右键或详情页出现“打开文件”“打开所在文件夹”，点击即调起资源管理器。这是下载器最高频动作。

### 接口

新增 `POST /api/reveal`，body `{id, mode}`：

| mode | 行为 |
|---|---|
| `open` | `explorer.exe <落点>` |
| `select` | `explorer.exe /select,<落点>` |

**只收 task id，不收客户端路径**。服务端从队列里取该任务自己的 `name` + `out-dir` 拼落点，
再过一遍 dlm 的落点闸（越出目录就拒）。理由：本地 HTTP 带 token 的边界是“本用户可调”，
但把任意路径交给 explorer 等于开了一个通用文件打开接口，没必要。

### 改动面

| 文件 | 改动 |
|---|---|
| `src/actions.rs` | `pub fn reveal_plan(mode, file) -> ActionPlan`（与既有 `plan` 同形的纯函数，便于单测） |
| `src/gui.rs` | 新路由 + `Ticket::Reveal`；落点取自队列，过 `task.rs` 的落点闸 |
| `src/ui.html` | 完成态任务行与详情页各加两个按钮；失败态只给“打开所在文件夹” |
| `README.md` | 「产品层」节补 `/api/reveal` 与“只按 task id 取路径” |

### 判据

- 纯函数：`reveal_plan` 两种 mode 的 argv 形状（`/select,` 是**一个**参数，不能拆成两个）。
- 集成：`POST /api/reveal` 带未完成任务 ⇒ 400；带未知 id ⇒ 404；带额外 `path` 字段 ⇒ 被忽略（且不改行为）。
- 集成：不真的启动 explorer（用注入的假 spawn，或断言返回体里 `spawned:false` 的 dry-run 分支）。
- 落点闸：任务名含 `..` 的任务构造不出来，所以这条用单元层直接测闸函数。

## P3 开机自启 + 单实例复用

### 目标

开机后队列自己在跑（不需要浏览器窗口），浏览器投递直接进队列；重复启动时不新起进程，而是复用已在跑的那个。

### 设计

1. **自启**：写 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`，值 `"<bin>\dlm-gui.exe" --autostart`。
   `--autostart` = 不打开浏览器窗口、不发任何网络请求，只监听环回并写端点文件。
2. **单实例**：启动时先读端点文件，能连上且 `GET /api/tasks?t=<token>` 返回 200 ⇒ 判定已有实例，
   打印它的 URL 后退出 0（带 `--open` 时改为打开那个 URL）。
3. **开关**：`install.ps1 -Autostart` / `uninstall.ps1` 移除；GUI 另给 `--autostart-install` / `--autostart-remove`。
   注册表写入走 `reg.exe add/delete`（与既有 `explorer.exe`、`shutdown.exe` 同一姿态，零新依赖），
   argv 由纯函数 `autostart_command()` 生成，可单测。

### 改动面

| 文件 | 改动 |
|---|---|
| `src/gui.rs` | `--autostart` 行为；`probe_existing_instance()`；`--autostart-install/remove` |
| `src/bin/dlm-gui.rs` | 三个新参数的解析与帮助 |
| `packaging/install.ps1` | `-Autostart` 开关（默认关） |
| `packaging/uninstall.ps1` | 兜底删除 Run 项 |
| `README.md` / `packaging/README-PACKAGE.md` | 自启位置、如何关闭、单实例口径 |

### 判据

- `autostart_command()` 纯函数：路径含空格时仍是一个 argv，带 `/d` 语义的正则引号。
- 单实例：起一个 `dlm-gui --port 0`，再起第二个 ⇒ 第二个退出 0 且**不**新监听端口（断言端点文件 pid 未变）。
- 反臂：端点文件存在但端口没人听 ⇒ 正常启动（陈旧文件不阻塞）。
- 真机：重启后 `%LOCALAPPDATA%\dlm\gui\endpoint.json` 的 `started_at` 在开机后更新，扩展投递成功。

### 风险

- 开机自启会常驻一个进程。默认**关**，安装器显式开关；README 写清怎么关。这是产品决定，安装时由你选。
- 注册表写入只碰 `HKCU\...\Run\dlm-gui` 一个值，卸载删同名值，不碰其它键。

## P4 UI 收尾

| 项 | 现状 | 改为 |
|---|---|---|
| 成功任务行 `exit 0` | 开发者语言 | 成功态不显示退出码，失败态才显示 |
| 弹窗/抽屉 Esc | 无 | `keydown` 关闭；打开时把焦点移进弹窗，关闭后还给触发按钮 |
| 焦点圈 | 无 | 弹窗内 Tab 循环（`focusin` 兜底即可，不做完整 trap 库） |
| 空态文案 | “队列为空。添加一个链接开始。” | 补一句“也可以从浏览器扩展直接投递” |

判据：`dlm-gui` 不新增后端；这四条用真浏览器 `browser/test/verify-gui.mjs` 扩一臂（Esc 关闭 + 焦点返回）。

## P5 托盘图标（本轮**不做**，只记账）

托盘要在零新 crate 下裸写 Win32 FFI：`RegisterClassW`、`CreateWindowExW`、`Shell_NotifyIconW`、
消息循环、`WM_COMMAND` 分发，约 400–600 行，且**无法在 CI/无头环境验证**，
只能靠人眼看。收益是“不用开浏览器窗口就能看进度”，而 P3 的 `--autostart` 已经覆盖“队列在跑”这件事。

⇒ 建议：先用 P3 跑一段时间，若“看不到进度”真的困扰，再单独立项 P5，届时要一并决定
是用裸 FFI 还是允许破依赖上限。

## 本轮明确不做

- 托盘图标（P5，见上）
- FTP / SFTP、DASH、DRM、音视频合并（协议扩展，与“手感”不同族）
- 剪贴板监控、站点抓取、系统计划任务、Windows 服务
- 队列优先级与失败重排（P1 只做自动重试，不做优先级排序）
- 队列透传 `--max-speed`（既有已知限制，另立项）
- 分类子目录之外的落盘策略变更（已交付 `--category-dirs`，不再动默认路径）
