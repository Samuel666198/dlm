### B. 范围决定："v1 不做什么" —— 14 项

不做守护进程 / 浏览器扩展 / Native Messaging / 站点抓取 / GUI / 限速配额 / 完成后动作链（杀软、关机）；
不处理 Ctrl-C 信号（= 你的第 6 项的延伸）；不自作主张改劈分规则压 dup（你的第 3 项）；
`--data-file` 那条路不试探、不读不写断点、不可续（E13④ / R13，理由是不能拿"无体 GET 探过的字节"给带体下载背书，
而"试探也发 POST"等于把同一份表单交第二次）；`prelude_max` 不发明 CLI 选项（R8）；
不写 `If-Range`（R9）；"见 416 即标完成"收窄成条件分支（R10）；不引入 `tokio`、不加第 7 个依赖；
`--user` 单独给（半副凭据）在明文 http 上**静默不发**，不报错（E28⑫，这条我当时判"评审说它跑了、我没复量" ⇒ 现已实测背书）；
`Report::trace` 不打 stdout（E20⑧）；`retries`/`duplicated` 是跨断点累计账、不当本次运行数印（E20⑨）。

### C. 测试与验收口径 —— 我定的规则，直接决定"什么算通过"

- 验收数一律写成 **floor（只许增、不许删、不许改判据方向）**，不写 exact（E26 之后立的）。
- 判据方向零放宽：整轮唯一被改写的判据是 8F-4b 的 ③ 号等式，改的是"它自己声明的价值"，不是期望值。
- 等价变异要警惕"两把口径在生产上恒等" ⇒ 只能靠自造夹具钉契约，注释必须写"钉的是契约、不是观测到的形状"。
- "两种写法没有可观测差别" ⇒ **不该有针**（不把死形状做成判据，避免下一轮又为它跑变异）。
- 负向判据必须与正向对照**成对**写进同一批用例，否则恒真假绿。
- 期望值**不许拿产品函数现算**；不许拿"帮助里名字像"当作覆盖到了（E30 新纪律：名字像 ≠ 覆盖到）。
- 变异结论只写**实测首红用例名**，不许写预测；执行者/评审者写的变异结论过夜后我要复跑。
