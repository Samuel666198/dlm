## 五分钟跑起来

```powershell
# 工具链与 PATH（本机 cargo 不在默认 PATH 里）
$env:PATH="C:\Users\ROG\.rustup\toolchains\stable-x86_64-pc-windows-msvc\bin;$env:PATH"
cd E:\WorkSpace\projects\tool\dlm

# 六道门禁，一条命令
powershell -NoProfile -ExecutionPolicy Bypass -File .\gates.ps1

# 打包（产出上面的 zip）
powershell -NoProfile -ExecutionPolicy Bypass -File .\packaging\build-package.ps1

# 扩展交互验收（起真浏览器跑真鼠标，不开宿主也能跑）
node browser\test\verify-ball-composed-events.mjs
node browser\test\verify-widget-ball.mjs
```

门禁是**地板不是天花板**：`fmt` / `--lib 374` / `--bins 4` / `--test integration 121` /
`clippy -D warnings` / 扩展静态检查。数字只许增，不许删测试、不许改判据方向。

`gates.ps1` 会设两个「门禁里别做真事」的变量：

- `DLM_NO_UPDATE_CHECK=1` —— 更新检查在启动 10 秒后请求外网，门禁里不许有真实外网请求
  （断网的机器会变红，联网的机器会悄悄依赖网络）。唯一测更新链路的那条集成用例
  自己 `.env_remove` 掉它。
- `DLM_NO_SHELL_OPEN=1` —— 「打开落点 / 在资源管理器里选中」不真的启动。
  否则一批用例会拉起 `explorer.exe` 指向 `target/harness-scratch/<pid>-<tag>-<n>/dl`
  这种**用例临时目录**；用例结束目录被删，屏幕上那个窗口随即弹
  「位置不可用 … 不可用」——**每跑一次门禁就在桌面留一个对话框**（2026-11-12 实测）。
  回执里的程序名/参数照旧按真实计划断言，只有 `spawned` 说 `false`。

## 产品结构（三层，界面别混淆）

| 层 | 入口 | 说明 |
|---|---|---|
| 内核 + CLI | `src/`、`dlm.exe` | 下载引擎：分段、断点续传、限速、配额、完成动作 |
| 原生 GUI | `src/gui/`、`dlm-gui.exe` | eframe/egui 真窗口 + 托盘 + 设置页；**同时是扩展的后端** |
| 浏览器扩展 | `browser/extension/` | 悬浮球、右键菜单、媒体/文件嗅探、HLS 直链 |

**关键**：`dlm-gui` 的 HTTP 服务是**产品接口**，不是"旧 Web UI 的残留"。扩展依赖它，
改它等于改公开接口。HTTP 只绑 `127.0.0.1`，所有路径都要 `?t=<token>`。

`dlm-native-host.exe` 是 Native Messaging 宿主（`com.dlm.host`），扩展 ID
`fkebhmogekekphpcggaclfgpfmofhdjk`，接口是 4 字节本机端序长度 + UTF-8 JSON。

## 必须知道的坑（都是实测撞出来的）

1. **eframe 0.37 的 trait 入口是 `fn ui(&mut self, ui: &mut egui::Ui, frame: &mut Frame)`**，
   不是老的 `update(ctx, frame)`。面板统一成 `egui::Panel::top/bottom/left(...).exact_size()`，
   `TopBottomPanel`/`SidePanel` 已经没有了。
2. **扩展改了必须重启浏览器**，只重开标签页不换 —— 旧代码还在内存里。用带
   `--load-extension` 的快捷方式启动（桌面/开始菜单/任务栏三个都配好了）。
3. **中文字体要运行时加载**：`default_fonts` 只有拉丁字母，中文会渲染成方块。
   现在从 `msyh.ttc` 起按序找（见 `src/gui/app/fonts.rs`）。
4. **工具栏图标不能用字符**（`＋ ▶ 🗑` 在微软雅黑里没有），一律用 `Painter` 画矢量。
5. **egui 只在有输入时重绘**，后台状态变化要自己 `ctx.request_repaint_after(...)`。
6. **两次并行**：队列 `--concurrency 2` × 每任务 8 连接 = 峰值 16 线程。按 host 限流必须做在
   队列层（errata E4），内核层做不到。
7. 布局常量按 **point** 算不是像素（E12）；`egui_kittest` 盖不到托盘/关窗/剪贴板（E11）。

## "点了没反应"这类问题怎么查（这三天换来的）

我在悬浮球这个问题上连错两次，方法比结论更值得传下去：

1. **别信合成输入。** CDP `Input.dispatchMouseEvent` 和操作系统的真实点击不等价，
   我用合成点击测出"能用"就下结论，浪费了一整轮。
2. **别急着归因外部。** 第一反应是"站点 `stopPropagation` 拦了事件"，
   实际上和事件传播毫无关系。
3. **把状态一层层打出来。** 在每一层写个标记（路由命中 → 处理函数进没进 → 状态变量值 →
   最终 DOM 属性），一次就能定位断点。这比读代码猜快一个数量级。
4. **直接读计算样式。** `getComputedStyle(host).display === "none"` 一量就结案，
   早该这么做而不是推理 `[hidden]` 和 `:host` 的优先级。
5. **验收脚本的测试页要有"空"的用例。** 之前所有测试页都带可下载链接，
   恰好绕过出故障的分支，所以永远全绿。

细节见 [`evidence/2026-11-11-extension-ball-fixes.md`](evidence/2026-11-11-extension-ball-fixes.md)。

### 同一类病的另一个变种：**界面在说谎**

2026-11-12 一天之内发现四处「界面有、实际不生效」，值得单独记：

| 现象 | 真因 |
|---|---|
| 设置里改连接数/限速不生效 | `child_args` 压根不传那两个参数（E18） |
| 剪贴板开关打开了没反应 | 命中后只 `eprintln!`，UI 没接（E19） |
| 下载目录改了没用 | `settings.effective_out_dir()` 零调用点 |
| 点任务条没有详情 | `DRAWER_W` 零引用，没人画抽屉 |

**共同的查法**：不要看界面有没有控件，要看**值有没有走到真正消费它的地方**。
`grep` 那个字段/函数的**调用点**，比读 UI 代码快得多 ——
「定义了但没人调用」是这类 bug 的统一形状。
