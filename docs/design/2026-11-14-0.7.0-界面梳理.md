## 一、先分清两类事

用户这一轮提的 7 条里，**四条是缺陷**（改对就完事，不需要设计），三条是**结构**（要改壳）。
把它们混在一轮做，会导致"改版没稳定、bug 也没觉得修完"。所以拆两批：

| 批次 | 内容 | 判据 |
|---|---|---|
| **0.6.1**（补丁） | 四条缺陷 | 每条都有可复现的判据；不动布局 |
| **0.7.0**（改版） | 壳与结构 + 图标 + 抓取页 + 明暗 | 整窗重排，配一套新截图 |

## 二、四条缺陷（0.6.1）

| # | 现象 | 根因（已定位） | 动作 |
|---|---|---|---|
| 1 | `Ctrl K` 没反应 | 快捷键**触发了**（探针实测 `hit=Some(OpenPalette)`），是面板自己没画：`Window::open(&mut close)` 传了初值 `false`，egui 把这个当成"窗口已关闭"，每帧跳过绘制 | 不传 `.open`；Esc 关闭照旧 |
| 2 | 点 `×` 不收起托盘 | 判据是 `close_to_tray && tray_available && busy`。截图那刻"0 个在跑" ⇒ `busy=false` ⇒ 直接退出 | 去掉 `busy`；托盘菜单补「退出」，否则开关打开后关不掉 |
| 3 | 长报错/长 URL 溢出窗口 | 日志 label 放在 `ui.horizontal(...)` 里 —— 横轴无限宽，永不换行，把窗口撑出去（`drawer.rs:377`） | 竖向 `ScrollArea` + 遇宽强制换行；URL 单行省略 + 悬停全文 |
| 4 | 详情里两个关闭按钮 | 窗口标题栏自带 `×`，`drawer_body` 里又画了一个（`drawer.rs:173`） | 只留一个 |

四条都能写死在用例里：`shortcut_for` 已有单测，缺的是"按键 → App 状态 → 真的画出来"这一段；
溢出与双关闭用整帧渲染 + 断言窗口尺寸不增长。

## 三、结构：三层壳

顶栏改了两处（第三轮反馈）：

- **「新建」按钮去掉，换成品牌位**（logo + `dlm` 字标）。入口已经在左栏平铺，顶栏再放一个橙色大按钮
  既是重复，也是把视线从内容上抢走。品牌位同时是窗口的"身份标识"。
- **搜索框从 `flex:1`（拉满）收窄到 340px**。它只搜任务名和链接，拉满整行会让人以为那是万能输入框；
  现在它缩在品牌右边，右侧留给快捷键提示和图标。

```
┌──────────────────────────────────────────────────────────┐
│ 顶栏   新建 · 搜索(Ctrl K) · 设置 · 更多                  │
├──────────────┬───────────────────────────┬───────────────┤
│ 左栏(可收起) │ 主区                      │ 右栏详情(可选) │
│  新建任务    │  批量条（多选时出现）     │ 名称   ×       │
│  站点抓取 ▸  │  列表 / 新建页 / 抓取页   │ 进度  速度     │
│  下载列表    │                           │ 落点  URL      │
│  任务(4 项)  │                           │ 日志（换行）   │
│  分类(7 项)  │                           │ 操作           │
├──────────────┴───────────────────────────┴───────────────┤
│ 状态栏   0 个在跑 · 限速 不限 · v0.7.0                    │
└──────────────────────────────────────────────────────────┘
```

三条关键取舍：

1. **入口从下拉里搬出来**。现在"新建 ▾"把三个入口藏在菜单里 —— 藏起来的功能等于没做。
   左栏顶部平铺，顶栏「新建」保留成快捷方式（点它 = 点左栏第一项 + 打开下拉）。
2. **详情从浮窗改成右栏**。浮窗会挡列表、还会被窗口边缘裁掉（第二张截图就是）。
   右栏宽度固定 320–340，主区让位，日志在框内换行滚动。
3. **任务操作搬到右键菜单 + 批量条**。选中就冒出一条按钮行，是"为了两次点击牺牲一行高度"；
   右键菜单能装下 8 条动作并带快捷键提示，批量条只在多选时占位。

## 四、图标

现状：`app/icons.rs` 只有 7 个自绘图标（`Plus Play Pause Trash Gear Dots ChevronDown`），
其余全是文字。方案：一套 16px 线稿图标，统一 1.5px 描边、24 视图框。**约 24 个，分四组**：

| 组 | 图标 | 用在哪 |
|---|---|---|
| 入口 | 新建(+) · 站点抓取(◎) · 列表(☰) · 下载(↓) | 左栏顶部三个入口、顶栏「新建」 |
| 任务状态 | 全部(☰) · 进行中(↓) · 已完成(◉✓) · 失败(◉!) | 左栏「任务」四项，**图标本身带颜色语义** |
| 分类 | 文档 · 视频 · 音频 · 压缩包 · 程序 · 图片 · 其它 | 左栏「分类」七项 + 列表里的类型标记 |
| 动作/杂项 | 播放 暂停 删除 文件夹 文件 复制 链接 收起 展开 时钟 重试 检查 警告 | 右键菜单、详情栏底、抽屉 |

三条约束（都是踩过的）：

1. **不用 Unicode 字符代替**。Microsoft YaHei 缺 `▾ ✓ ✕ ⋯ ＋ ▶` 那批字形，会画成空心方框
   （0.6.0 阶段 1 的教训，`every_symbol_we_put_in_the_ui_has_a_glyph` 守着）。
2. **状态图标带颜色**：进行中=强调色、已完成=绿、失败=红。只靠文字标签时，一列下去全是黑字，
   眼睛要读字才分得清；图标带色可以扫过去。
3. **分类图标与 `queue::category_for` 一一对应**，不要另造一套分类。左边栏、列表类型列、
   抓取结果表共用同一张映射，否则"分类"这个词会在三处指三个东西。

**注意**：不能用 Unicode 字符代替 —— Microsoft YaHei 缺 `▾ ✓ ✕ ⋯ ＋ ▶` 那批字形，
会画成空心方框（0.6.0 阶段 1 的教训，`every_symbol_we_put_in_the_ui_has_a_glyph` 守着）。

### 收起态（52px）的四个细节

用户第二轮截图里红框标的是第二个入口：**收起后 `▸` 箭头还在**，把窄条挤歪了。同一处还藏着三个问题：

| 问题 | 现象 | 修法 |
|---|---|---|
| 箭头没藏 | 「站点抓取」那行比别的宽，图标被挤偏 | `.mini .car { display:none }` |
| 分组消失 | 「任务」和「分类」标题一藏，14 个图标连成一片，分不清哪段是哪段 | 用 24px 宽的分隔线代替组标题 |
| 箭头方向 | 收起后仍然是 `‹`（指向左），看着像还能往左收 | 收起时翻转 180° |
| 认不出图标 | 只剩图标，不知道点哪个 | 每项 `title` 悬停提示（egui 里是 `on_hover_text`） |

## 四点三、顶栏与状态栏（第四轮反馈）

| 你的意见 | 改法 | 理由 |
|---|---|---|
| 搜索框放到那一整条 | 占满品牌与右侧图标之间，`flex:1` | 上一轮收窄到 340 是把问题解决错了：真正刺眼的是它**太重**，不是太长 |
| Ctrl K 标识嵌进输入框 | 移到框内右端，`opacity:.7` | 外置的快捷键提示像第二个按钮；嵌进去才像"输入框的一部分" |
| 不透明度调整 | 常态 `opacity:.86` + 透明底 + 无边框，悬停才显形 | 搜索是常用但非主角，不该用一块实底面板压住视线 |
| 收起图标用「面板」图形 | 换成图上那种带左栏的圆角方框，左对齐 | 尖括号是"翻页"，面板图标才是"收侧栏" |
| 收起后界面会缩 | 状态栏从侧栏底部搬到**窗口底部** | 「N 个在跑 · 限速」属于窗口，不属于侧栏；挂在侧栏上就注定跟着收放缩水 |

## 四点四、设置窗

固定 **720×440**，七个分类（下载 / 连接与速度 / 限速计划 / 代理 / Agent 接入 / 界面 / 高级），
分类项**带图标**，右侧内容区内部滚动。判定标准只有一条：**逐个点七个分类，窗口尺寸一动不动**。

三条设计决定：

1. **固定尺寸，内容滚动**。原来高度跟着内容走，切个分类窗口就跳一下，眼睛要重新找位置。
   固定之后"保存/取消"也在固定位置，肌肉记忆能建立。
2. **文案一句一条事实，≤16 字**。原来那句「留空 = 系统下载文件夹；视频/音频/压缩包各进一个子目录；
   只影响新任务」把三件事塞进一个句子。现在拆成标题 + 一句灰字，机制细节收进悬停提示。
3. **每个分类都归位，不留「其它」**。七个分类是穷举的：加一个设置项必须归类，否则
   `every_settings_field_has_exactly_one_spec` 会红（0.6.0 已建立的机械检查）。

«界面» 这页是新增的：语言、主题、密度、启动收起侧栏、关窗收托盘、首次提示。
其中「关闭窗口时收进托盘」正是这一轮那个 bug —— 开关的字面意思必须就是开关。

## 四点五、Ctrl K 命令面板

顶栏搜索框、`Ctrl K`、以及"没找到想点的东西时的最后一条路"——三者是同一个东西：命令面板。

布局（见可视稿，按 `Ctrl K` 或点搜索框都能打开）：

```
┌───────────────────────────── 470px ─────────────────────────────┐
│ 🔍 输入命令，或直接搜任务…                                Esc   │
├─────────────────────────────────────────────────────────────────┤
│ 搜索                                                             │
│ 🔍 搜索任务                              search tasks             │
│ 新建                                                             │
│ ＋ 新建下载                              new download   Ctrl N    │
│ ◎ 站点抓取                               site grab                 │
│ ⧉ 批量粘贴                               paste links   Ctrl V     │
│ 任务                                                             │
│ ⏸ 全部暂停                               pause all                │
│ 🗑 删除全部已完成                         clear completed          │
│ 跳转                                                             │
│ ⚙ 设置                                   settings      Ctrl ,    │
│ 📁 打开保存目录                            open download folder    │
│ ↻ 检查更新                                check for updates       │
├─────────────────────────────────────────────────────────────────┤
│ ↑↓ 选择   ↵ 执行   Esc 关闭                                     │
└─────────────────────────────────────────────────────────────────┘
```

四条设计决定：

1. **第一项永远是「搜索任务」**。设计稿原话是"面板是升级过的搜索"——想搜的人多按一次回车就回到
   原来的行为，想找命令的人在这里看到全部。`Ctrl F` 保留直接聚焦搜索框，老习惯不变。
2. **中英双列**。中文名在前（主），英文名在后且浅色（能搜到，但不抢视线）。
   这解决了"记得那个命令怎么拼、但中文叫什么"和反过来的两种情形，**不需要先做 i18n**。
3. **分组而不是一长条**。搜索 / 新建 / 任务 / 跳转四组。一长条在 8 条以上就开始扫视困难。
4. **快捷键写在右边**。抄 VS Code：看得见才会用得上，用着用着就不点按钮了。

界面只有一个输入框、一个列表、一行提示。**不做**以下三件：模糊匹配高亮（假功能，让人以为能搜到
搜不到的东西）、最近使用（顺序已经按频率排好）、嵌套子命令（一层足够）。

## 五、站点抓取页重排

现在是一张表单从上往下堆：起始页 → 范围 → 模板 → 扫描 → 结果。
提案分三步（地址 → 范围 → 清单），配"模板"独立卡片：

- **地址**：起始页 + 一键从剪切板取；
- **范围**：包含/排除 + 深度 + 只抓同站 + 跟随翻页；
- **清单**：扫描后原地变成结果表（勾选 · 文件名 · 类型 · 来自 · 已去重），不再换页；
- **模板卡**常驻右侧，点一下套用，命名后可存。

## 六、明暗主题

`theme.rs` 里 15 个颜色常量是手绘的一套暖色。深色不是"反色"：

- 背景 `#191713` / 面板 `#211E19`，强调色要提亮到 `#D87E58`（原 `#C06340` 在深底上发闷）；
- 语义色（ok / warn / bad）在深底上要重新配，否则"已完成"的绿几乎看不见；
- 每屏都要重看对比度，尤其进度条底 `track` 与填充 `ok` 的差。

成本：一套 token + 逐屏核对 ≈ 一轮。**不做"跟随系统"以外的花活**（不做毛玻璃、不做主题编辑器）。

## 六点五、字体与全称（待你定）

**字体。** 稿子里加了「无衬线 / 衬线」切换，可以直接对看。技术上有几件事要知道：

- 现在用的是 `Microsoft YaHei UI`，**无衬线**。Windows 上的中文衬线基本只有 `宋体(SimSun)`，
  它的小字号渲染很糟（点阵感重、粗细不匀）；装过 `思源宋体 / Noto Serif CJK` 才好看。
- 所以我倾向：**品牌字与标题用衬线，正文与控制件仍用无衬线**。全篇衬线在 10.5–12px 的
  界面字号下会发虚，而且表格数字对不齐。
- 若你坚持全篇衬线，我会把字号整体上调 0.5–1px 并换行高，否则读起来累。

**全称（已定）。** 界面里**不出现缩写**，品牌名直接用英文全称 **Download Manager**，加粗。
缩写 `dlm` 只留在文件名与命令上（`dlm.exe` / `dlm-gui.exe` / `dlm --url`）—— 那是路径，
不是品牌。界面内可读位置（顶栏、窗口标题、关于）一律用全称。

需要同步的四处：

| 位置 | 现在 | 改成 |
|---|---|---|
| 顶栏品牌位 | `dlm` + 中文副标题 | **Download Manager**（粗体） |
| 窗口标题 | `dlm` | `Download Manager` |
| 安装包 / 开始菜单 | `dlm` | 保留 `dlm-gui.exe` 文件名（路径不动），显示名改全称 |
| `--version` | `dlm 0.1.0` | `Download Manager 0.7.0 (dlm 0.1.0)` —— 命令里仍要能搜到 dlm |

## 七、需要拍板

| 问题 | 选项 | 我倾向 |
|---|---|---|
| 设置用**对话框**还是**页面**？ | 对话框（现在的样子，固定 720×440）／换成主区里的一页 | 对话框。它是"改完就关"的东西，占一整页显得重 |
| 详情放**右栏**还是**浮窗**？ | 右栏（固定、不挡列表）／浮窗（可拖走） | 右栏。浮窗在窄窗口下必被裁 |
| 批量选择怎么触发？ | 每行复选框（始终可见）／Ctrl 多选 + Shift 连选／两者 | 复选框 + Ctrl 多选。复选框是给鼠标用户的，Ctrl 是给键盘用户的 |
| 侧栏收起后要不要保留图标？ | 收到 52px 只留图标／完全收到 0（用一个悬浮按钮唤出） | 留图标条。完全收起会让人找不到入口 |
| 收起态怎么处理分组？ | 藏掉「任务/分类」标题（用分隔线代替）／保留极小字标题 | 分隔线。52px 放不下 10px 的组名，硬塞就是两行乱码 |
| 明暗开关放哪？ | 设置里（界面分类）／状态栏一键切／两者 | 设置里 + 状态栏跟随（不做常驻按钮，避免界面噪音） |

## 八、不做（这一轮明确排除）

- **中英双语**：所有文案都硬编码在中文字符串里，得先抽一层 Locale（几百条）。
  现在抽 = 一边搬家一边装修。等 0.7.0 布局稳定后单独一轮。
- **主题编辑器 / 自定义配色**：不是现在的痛点。
- **可拖拽分栏宽度**：右栏固定宽度更省事，等真的有人抱怨再说。
