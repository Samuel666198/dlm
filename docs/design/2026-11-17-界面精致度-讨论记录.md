## 一、根源诊断（都是量出来的数，不是印象）

### 1.1 两套度量并存，从没统一

| 度量 | 现状 | 问题 |
|---|---|---|
| 字号 | **12 档**：9.5 / 10 / 10.5 / 11 / 11.5 / 12 / 12.5 / 13 / 14 / 15 / 20 / 44 | 6 个值挤在 10–12.5（10.5 用了 46 次、11.5 用了 31 次），肉眼分不出层级 |
| 间距 | **11 档**：2 / 4 / 6 / 8 / 9 / 10 / 12 / 14 / 16 / 18 / 26 | 没有 4 或 8 的阶梯，全靠手感 |
| 圆角 | **6 种值**：0 / 1 / 4 / 6 / 7 / 99 | `theme::RADIUS = 9` 全仓**只用了 2 次**（`icons.rs:132`、`toolbar.rs:200`），所谓"统一圆角"等于没统一 |
| 阴影 | **零**。全仓搜 `shadow` 无命中 | 卡片/菜单/弹窗全是硬边贴底 |
| egui 自身 Style | **完全没接管**：`item_spacing` 仍默认 `(8, 3)`、`button_padding` `(8, 2)`、`window_margin` `6` | 手绘控件按一套度量排，egui 原生控件按另一套排 —— 看着像"没做完" |

**结论**：粗糙感的直接来源不是"少了特效"，是**没有一套度量**。

### 1.2 颜色层次只有一半（用户指出的"颜色太接近"）

实测对比度与 CIELAB ΔE（判据：ΔE<2 看不出、2–5 微妙、>5 明显分层）：

| 对比 | 对比度 | ΔE | 判读 |
|---|---|---|---|
| paper → surface（纸底→卡片） | 1.090 | **3.61** | 只能"看出一点" |
| paper → surface3（设计稿有、实现没有） | 1.036 | **1.39** | **肉眼看不出** |
| surface → surface_2（卡片→次级） | 1.052 | 2.32 | 很微妙 |
| 深色 paper → surface_2 | 1.156 | 8.28 | 深色反而更分得开 |

三处结构性缺陷：

1. **设计稿有第三层表面，实现没有。** 设计稿 `:root` 写了 `--surface3: #FAF7F0`（浅）/ `#1D1A16`（深），
   专门给卡片内嵌块、模板卡用。Rust `Palette` 里**没有这个字段**（搜 `surface_3` 零命中）。
   于是"需要再低一层"的地方只能复用 `surface_2`，而它本来是 hover 色 —— 一个色值被迫承担两个语义，层次被压平。
2. **`ink_3` 在浅色下不合规。** 实测：ink 13.44 / ink_2 5.00 / **ink_3 2.62**（WCAG AA 正文要求 4.5，
   大字号或 UI 元素要求 3.0）。它被用在副标题、灰字说明、计数上 —— 既不够淡（退不进背景）也不够深（承担不了信息），卡在中间。
3. **`surface_2` 语义重载。** 全仓 8 个文件 15 处调用它，既当"次级底"又当"hover 底"。

### 1.3 egui 做不出高斯模糊阴影（约束）

设计稿的 `--shadow: 0 12px 34px rgba(42,39,32,.12)` 是 CSS 模糊阴影。
`epaint::Shadow` 只有偏移 + 扩散，**没有高斯模糊**。所以立体感只能走：
1px 亮/暗双边描边 + 相邻表面 ΔE ≥ 5。这也说明**先拉开表面阶梯是加描边的前提**。

## 三、重复品牌标识：这是系统标题栏，不是多余代码

**实况**：图 1 红框里那两处，上一处是 **Windows 原生标题栏**（显示窗口标题 `Download Manager`），
下一处是 `toolbar.rs:169` 的 `brand_block`（自绘：陶土橙方块 + 下载图标 + 粗体 `Download Manager`）。
不是画了两遍，是**系统那份 + 我们那份**。

**为什么会有两份**：`docs/superpowers/specs/2026-11-10-native-shell-errata.md` 的 **E10** 明确裁定过：

> demo 是自绘标题栏（34px），要 `with_decorations(false)` + 自己写拖拽/缩放/最大化/贴边，
> 并**失去 Win11 圆角、阴影、Snap Layouts**。
> **默认按 A 实现**（原生装饰），因为下载器不是设计作品，系统一致性更重要。

所以 `brand_block` 是这条裁定的**遗留矛盾**：选了原生标题栏，又保留了自绘品牌位。

**三种解法**（都需要你定，因为都是取舍，没有对错）：

| | 做法 | 得到 | 失去 |
|---|---|---|---|
| **S1** | 删 `brand_block`，顶栏从搜索框开始 | 零重复、零技术风险、改动最小 | 顶栏左侧 180pt 变空，品牌只活在标题栏里（也够） |
| **S2** | `with_decorations(false)` 自绘标题栏，把品牌位并进去 | 完全对齐设计稿 v3，一份品牌标识，可控外观 | 要自己实现拖拽/缩放/最大化/贴边/Win11 圆角+阴影+Snap Layouts；**推翻 E10 已定裁定** |
| **S3** | 保留两份但差异化：标题栏由系统显示全称，品牌位缩成一个纯图标（不带文字） | 视觉上只有一份"文字品牌"，图标当识别符 | 仍有两处图形元素，只是不重复文字 |

**我倾向 S1**：下载器确实不是设计作品，E10 的理由仍然成立；而"顶栏左边空一点"配合后面要做的
搜索框左移，反而更像现代工具（很多现代应用的顶栏只有搜索/命令入口）。
但 **S2 是唯一能同时解决"现代化观感"和"重复品牌"的路** —— 如果你觉得原生标题栏本身就是"不够现代"的一部分，那就得选 S2，并接受它推翻 E10。

## 四、"五彩斑斓的白"——需要你确认我理解得对不对

这个词在 UI 里通常指两种完全不同的东西，做出来差别极大。我按可能性列出来，你指一个（或者说都不是）：

**理解 A：极低饱和的多色点缀（我最倾向这个可能）**
底色仍是暖白，但在**不同功能区域**用极淡的不同色相区分——不是随机彩虹，
而是"每个语义有自己的极淡底色"。比如：已完成淡绿、进行中淡蓝、失败淡红、分类图标各自淡色相。
关键词是**低饱和**（明度差小、饱和低），远处看是白，近看有色彩倾向。
技术上完全可行（改色板即可），且能和 §1.2 的表面阶梯叠加。

**理解 B：文字/描边的彩虹渐变**
品牌名、进度条、状态条用 HSL 彩虹渐变。egui 支持逐顶点着色，
所以线性渐变**能做**；但彩虹渐变在工具软件里通常显廉价，而且会和"克制的暖纸 + 陶土橙"这套定调冲突。

**理解 C：表面光泽（"白"本身五彩斑斓）**
类似珍珠白 / 渐变镀膜的观感——非常淡的多色渐变铺在卡片表面。
这个需要渐变 + 多色叠加，egui 能做线性渐变但做不到真正的高光/漫反射，"珍珠白"效果达不到，
只能做到"极淡的斜向多色渐变"。**我会诚实说：这条路在 egui 里只能做到七成。**

**我建议先做 A**：它是唯一既"多彩"又不破坏现有克制调性的方案，且实现代价最小、风险最低。
如果你想要的是 B 或 C，我建议先做一个**单页 spike（一次性试验）**让你眼睛看，再决定要不要全铺——
因为这两个的观感争议最大，纯文字讨论不如看一眼。

**这一步需要你回答**：我上面 A / B / C 哪个接近你说的意思？还是都不是，你是指别的？

## 七、我最终定下的色板（2026-11-17，已用 ΔE / WCAG 算过）

**决策权在用户交给我的范围内行使，以下是依据，便于日后复盘或推翻。**

### 7.1 为什么是四层表面，而不是更多

浅色里从"纸底"到"纯白"的可用跨度只有约 12 ΔE。四层要相邻都 ≥5 就得吃掉 15 ΔE ——
那只能靠纯白/纯黑，搜索最优解时确实跑出了 `paper #000000 / surface #FFFFFF` 这种废解。
所以**门槛按职责定，不搞一刀切**：

| 对 | 门槛 | 理由 |
|---|---|---|
| `sunken → paper` | ≥ 5.0 | 凹槽（输入框/进度条轨道）必须看得出凹，否则和纸底粘在一起 |
| `paper → surface` | ≥ 5.0 | **卡片浮起感的核心**，这是"没层次"的主因（原来只有 3.61） |
| `paper → surface3` | ≥ 3.0 | 内嵌块靠 1px 描边区分，不该跟主卡片抢注意力 |
| `surface3 → surface` | ≥ 3.0 | 同上，故意做淡 |

### 7.2 定稿色值

| 层 | 浅色 | 深色 | 语义 |
|---|---|---|---|
| `sunken` | `#E1D8C5` | `#0D0B09` | 输入框、进度条轨道（凹进去） |
| `paper` | `#EDE6D8` | `#1C1915` | 窗口底 |
| `surface3` | `#F8F4EC` | `#282319` | 卡片内嵌块、模板卡、代码块 |
| `surface` | `#FFFDF7` | `#332D24` | 主卡片、列表行、浮层 |

文字（`ink` / `ink_2` / `ink_3` / `ink_4`）：

| token | 浅色 | 深色 | 对比度（paper） | 用途 |
|---|---|---|---|---|
| `ink` | `#2A2720` | `#F4F0E8` | 12.00 / 15.41 | 正文、标题 |
| `ink_2` | `#575246` | `#C6BFB2` | 6.26 / 9.59 | 次级正文 |
| `ink_3` | `#6B6555` | `#A79F91` | **4.67** / 6.68 | 说明文字（旧版 2.62，**不合规**） |
| `ink_4` | `#A69F91` | `#6B655A` | 2.12 / 3.03 | **仅装饰/禁用**，不承载信息 |

### 7.3 实测达成（脚本 `target\_palette5.py`，0 项失败）

| 指标 | 旧 | 新 |
|---|---|---|
| 浅色 `paper→surface` ΔE | 3.61 | **9.06** |
| 深色 `paper→surface` ΔE | 3.76 | **10.50** |
| 浅色 `ink_3` 对比度 | 2.62（不合规） | **4.67（AA 正文合格）** |
| 暖纸调性（R>G>B） | — | 四层全部保持 |

### 7.4 语义搬迁（这次最重要的结构变化）

- **新增 `surface_3`**：把设计稿里 `--surface3` 补上。以前"需要再低一层"只能借 `surface_2`。
- **`surface_2` 改邪归正**：从"既当次级底又当 hover"里解放出来，**只做 hover / 选中底**。
  这就是层次感的真正来源：每个色值只承担一个语义。
- **新增 `sunken`**：输入框、进度条轨道从 `surface_2` 换到它，凹槽才立得起来。
- **新增 `ink_4`**：把"淡"和"看不清"分开 —— 淡的只给装饰用。

### 7.5 立体感怎么来（egui 没有高斯模糊）

`epaint::Shadow` 只有偏移 + 扩散，做不出 CSS 那种 `0 12px 34px` 的模糊。
所以立体感走两条：**表面 ΔE 阶梯（上面已做到 9~10）** + **1px 亮/暗双边描边**
（卡片上沿取 `surface` 提亮一档、下沿取 `line`）。层次分开之后描边才有意义；
层次没分开时描边只是脏边。

## 六、过渡动画（2026-11-17 新增）

用户："可以做一些过渡动画，减少一些突兀感。"

### 6.1 现有基础（查过）

| 项 | 实况 |
|---|---|
| egui 动画 API | `animate_bool(id, bool) -> f32`、`animate_bool_responsive`（cubic_out）、`animate_value_with_time`，都在 `Context` 上 |
| 默认时长 | `Style.animation_time = 0.2` 秒（0.37 实测） |
| 项目现状 | **从未主动用过动画**（搜 `animate_bool` / `animate_value` 零命中），全靠 egui 对原生控件的默认行为 |
| 门禁影响 | **没有像素/渲染回归测试**，门禁也不查截图 ⇒ 动画**不会**打假红，但也**没有回归保护** |

### 6.2 能做 / 做不动（诚实边界）

**能做**：
- 面板**宽度**插值（侧栏 212↔52、右栏详情 0↔330）—— 纯 f32 插值，`columns()` 每帧跟着重排，天然平滑
- 自绘控件的 **hover / 选中**过渡（每行一个 Id，`animate_bool`）
- 进度条**填充宽度**插值（现在是每帧跳变，改成向目标值逼近）
- 悬浮岛出现/消失的**位移 + 透明度**（自己画，可控）

**做不动 / 不值得**：
- **弹窗淡入**：egui 的 `Window` 没有开场动画，要做只能把全部颜色乘一个 alpha，
  而全仓上百处 `theme::ink()` 取色，等于大改 —— 不做
- **毛玻璃 / 高斯模糊**：`epaint::Shadow` 只有偏移+扩散，没有模糊（§1.3 已记）
- **弹簧物理**：egui 只有线性/三次缓动，没有 spring。硬做要自己写积分器，
  对"减少突兀感"这个目标属于过度工程
- **列表行插入动画**：立即模式下每帧重画，行没有稳定身份动画，容易闪烁

### 6.3 关键风险（必须先说）

1. **动画要持续重绘**：`animate_bool` 会在动画期间自动 `request_repaint`，
   但自绘的宽度插值如果不显式请求重绘，会卡在半路。这是最容易写错的地方。
2. **宽度动画 × 列宽自适应有耦合**：右栏展开时 `columns()` 每帧按新宽度重算，
   动画期间会看到"文件名列一路缩、速度列在某个宽度突然消失"的跳变
   —— 这正是 `list.rs:55` 那套 `show_speed` / `show_eta` 的阈值判断。
   要么给阈值加滞回（hysteresis），要么动画结束后才允许列切换。
3. **门禁无像素回归**：动画错了没人拦。只能靠 `agent-desktop` 连拍几帧看，
   或者给插值函数本身写纯函数用例（推荐，和现有风格一致）。

### 6.4 我建议的顺序（按"突兀感 ÷ 风险"排）

| 优先 | 动画 | 为什么 |
|---|---|---|
| 1 | 右栏详情滑入/滑出（0↔330 宽度插值） | 突兀感最强的一处：330pt 面板凭空出现 |
| 2 | 侧栏收起/展开（212↔52） | 同上；且和已经做的高亮强调条直接配套 |
| 3 | 批量悬浮岛 出现/消失（上浮 + 淡入） | 用户明确说"突然出现很突兀"，这条就是它的解药 |
| 4 | 进度条填充插值 | 每帧跳变，改完整个列表观感立刻不同 |
| 5 | 行 hover / 选中 过渡 | 收尾级；等视觉规范定了再一起做 |

**前置依赖**：1/2/3 都要等 §2 的布局改动（悬浮岛、删上下文条、pane 化）先落地，
否则动画做在马上要挪走的控件上，等于白做。

**待用户确认**：这 5 条是全做，还是先做 1+2+3（最突兀的三处）。
