## 一、已确定的决定

| # | 决定 | 理由 |
|---|---|---|
| 1 | 品牌名用英文全称 **Download Manager**，加粗；界面内不出现 `dlm` 缩写 | 缩写只留在文件名与命令上（`dlm.exe`、`dlm --url`） |
| 2 | 顶栏不再有「新建」按钮 | 入口已在左栏平铺，重复且抢视线 |
| 3 | 搜索框：撑满但设 560px 上限、左移 26px、半透明、Ctrl K 内嵌右端 | 刺眼的是"太重"，不是"太长"；上一轮收窄到 340 是解决错了问题 |
| 4 | 左栏顶部平铺三个入口：新建任务 / 站点抓取 / 下载列表 | 下拉里藏的入口等于没做 |
| 5 | 侧栏可收起为 52px 图标条，图标带 `on_hover_text` 提示 | 完全收成 0 会让人找不到入口 |
| 6 | 收起态用分隔线代替「任务/分类」组标题 | 52px 放不下 10px 组名，硬塞就是乱码 |
| 7 | 状态栏（进行中 N 项 / 限速）挂在**窗口底部**，不挂侧栏 | 挂侧栏就注定跟着收放缩水 |
| 8 | 任务详情改为**右侧固定栏**（330px），单关闭按钮 | 浮窗挡列表、窄窗口下必被裁；原有两个关闭按钮是重复 |
| 9 | 长日志/长 URL 在框内**自动换行 + 竖向滚动** | 现在放在 `horizontal` 里 → 横轴无限宽 → 永不换行 → 把窗口撑变形 |
| 10 | 任务操作迁到**右键菜单**（带快捷键提示）+ 多选后的**批量条** | 选中就冒一条按钮行，是拿整行高度换两次点击 |
| 11 | 批量选择 = 每行复选框 **+** Ctrl 多选 | 复选框给鼠标用户，Ctrl 给键盘用户 |
| 12 | 命令面板（Ctrl K）：四组十一条，中英双列，快捷键右挂 | 第一项固定为「搜索任务」，兼容原来的 Ctrl F 习惯 |
| 13 | 设置窗固定 **720×440**，内容内部滚动，八个分类带图标 | 切分类时窗口跳动，眼睛要重新找位置 |
| 14 | 设置文案一句一条事实 ≤16 字，机制细节进灰字 | 原来一句里塞三件事 |
| 15 | 新增「界面」页：语言 / 主题 / 密度 / 启动收起侧栏 / 关窗收托盘 / 首次提示 | 「关窗收托盘」正是这轮那个 bug |
| 16 | 明暗主题：手绘 token 重配一套，语义色（ok/warn/bad）必须重调 | 深底上"已完成"的绿几乎看不见 |
| 17 | 抓取页分三步：地址 → 范围 → 清单，模板独立成右侧卡片 | 现在是一张表单从上往下堆 |
| 18 | 图标 24 个，四组（入口 / 任务状态 / 分类 / 动作），**不用 Unicode 字符** | Microsoft YaHei 缺 `▾ ✓ ✕ ⋯ ＋ ▶`，会画成空心方框 |
| 19 | 任务状态图标**带颜色语义**（进行中=强调、已完成=绿、失败=红） | 一列黑字要逐行读才知道哪行失败 |
| 20 | 分类图标与 `queue::category_for` **共用同一映射** | 否则「分类」一词在三处指三个东西 |
| 21 | 设置里那个「浏览器扩展」页**升级为「组件」页**：一页管四个组件（桌面端+内核 / MCP 桥接 / 浏览器扩展 / 更新通道），统一成四态（正常 / 需处理 / 未安装 / 未知）+ 每个组件 1–2 个动作；原先「高级」页顶部的版本块并入这里 | 2026-11-16 定。原来四个数散在高级页、扩展页、Agent 页与状态栏四处，同一个"扩展版本"在三处指三样东西；问一遍要翻四个地方 |
| 22 | 组件状态里 **「未知」与「未安装」必须分开** | "探测不到"写成"未安装"会让人去重装一个本来就装着的程序。扩展没连上、读不到版本、没检查过，一律 `Unknown` |
| 23 | MCP 的「获取」升级为**站内直接下载并安装**（拼直链 → 下载 → 解压 → 装前跑一次 `--version` → 落盘），发布页只作为 404 时的兜底 | 把下载、解压、放对目录三步手工活丢给用户，等于这个入口只做了一半 |

## 二、明确不做（这轮）

| 项 | 为什么 |
|---|---|
| 中英双语切换 | 文案全硬编码在中文串里，需先抽 Locale（几百条）。现在抽 = 一边搬家一边装修 |
| 主题编辑器 / 自定义配色 | 不是当前痛点 |
| 可拖拽分栏宽度 | 固定宽度够用，真有人抱怨再说 |
| 命令面板的模糊匹配高亮 | 假功能，让人以为能搜到搜不到的东西 |

## 四、Agent 接入页：补下载入口

问题：MCP 侧本来就支持"自定义下不下"（`agent_confirm`），但设置页只给了一段配置文本，
用户没法在界面里把它装上。改法：

```
MCP 桥接（dlm-mcp）
  获取 dlm-mcp        未安装 · 单独分发，约 2 MB          [下载]
  安装位置            置于桌面端同目录可自动识别           [未安装]
  复制 MCP 配置       自动定位端点文件，无需填写 token     [复制配置]

权限
  Agent 添加任务需人工确认   启用时仅生成待确认票据，确认后加入队列   [开关]
  待确认票据有效期           超时自动作废，与拒绝分别记录            [5 分钟]
```

「下载」按钮的行为：打开 Release 上那个单独附件（`dlm-mcp-<版本>-win-x64.zip`），
不是自己造一个下载器去下 —— 下载器的下载由 `dlm` 自己做，但这里只需要打开浏览器，
少一层出错可能。下载完成后回来检测同目录有没有 `dlm-mcp.exe`，有就把那行变成 `0.6.0 ✓`。

## 四点五、版本可见性

三个组件各自独立升级，用户排查问题时第一个要问的就是"你装的哪个版本"。所以：

**两处显示**（不是一处，因为用途不同）：

- **各自页面**（就地判断）：Agent 接入页显示 `dlm-mcp 版本 · 已安装 / 本程序要求 ≥ 0.6.0（api 2）`；
  浏览器扩展页显示 `已安装版本` 与 `随本程序提供` 两行（两个数不一致 = 该重载了）。
- **高级页「版本」卡**（一眼看全）：桌面端 / 下载内核 / 浏览器扩展 / MCP 桥接 四项 +
  一个「复制版本信息」按钮，把四项拼成一行文本，便于贴到 issue。
- **状态栏右下角**的 `v0.7.0` 悬停显示四项摘要 —— 不占地方，但随手能看。

**四个数从哪来**（实施时按这个取，别各写一套）：

| 组件 | 来源 | 备注 |
|---|---|---|
| 桌面端 | `gui::RELEASE` 常量 | 用户感知的版本 |
| 下载内核 | `dlm.exe --version` 输出 | 现成：`dlm 0.1.0` |
| 浏览器扩展（随包） | 读包内 `browser/extension/manifest.json` 的 `version` | 现成，打包脚本已这么读 |
| 浏览器扩展（运行中） | `POST /api/ext-hello` 上报的 `manifest.version` | **已实现**，0.6.0 就接好了，只是没用到界面上 |
| MCP 桥接 | `dlm-mcp --version` | **需要新增**：现在它只跑 stdio，没有 `--version`。加一个输出 `SERVER_VERSION` 的分支即可 |

## 五、浏览器扩展能不能由桌面端管理

**结论：能管，但不能"替浏览器装/更新"。** Chromium 明确禁止程序化安装或更新**已解压**
（unpacked）扩展 —— 这是安全边界，不是实现难度问题。能做的有四件，前三条无侵入：

| 做法 | 可行性 | 说明 |
|---|---|---|
| 1 版本对账 | ✅ 已具备 | 扩展连上宿主时上报自身 `manifest.version`（`POST /api/ext-hello`，已实现）。桌面端拿它与包内版本比对，不一致就提示 |
| 2 一键复制路径 / 打开扩展页 | ✅ | 复制 `browser/extension` 绝对路径；`chrome://extensions`、`edge://extensions` 用默认浏览器打开。**不能代点「重新加载」** |
| 3 重新导出到固定目录 | ✅ | 覆盖到 `%LOCALAPPDATA%\dlm\extension`，用户原路径还能继续用 |
| 4 策略强制安装（可自动更新） | ⚠️ 可选 | 写注册表 `ExtensionInstallForcelist` + 自建 CRX 与 update.xml。企业环境可行，但需要：把扩展发布成 CRX、托管 update 清单、写 HKLM/HKCU（要管理员确认）。**默认关闭** |

所以设置里新增「浏览器扩展」页，放 1–3，第 4 条做成一个开关并标明"需管理员权限"。
文案要诚实：**"本程序无法代为更新，需在扩展页手动重新加载"** —— 不写成"自动更新"。

## 七、代码影响提示（实施时会碰到的既有约束）

- 设置分类从 7 变 8：要同时改 `settings_spec::Category`、`SPECS` 归属，以及
  `every_spec_belongs_to_one_of_the_seven_categories` 这条用例（名字里带 seven，得改名）。
- 窗口标题改为 `Download Manager`：`ViewportBuilder::with_title` 与托盘 tooltip 两处。
- 新增图标要过 `every_symbol_we_put_in_the_ui_has_a_glyph`（若用字体无关的自绘图形则不受限）。
- 右栏详情会改变列表可用宽度：`RIGHT_SIDE_W` 一类常量与表格列宽要一起调。
- 侧栏收起状态要持久化 → `Settings` 新增字段 + `settings_spec` 新增一条（否则用例红）。
- `dlm-mcp` 要新增 `--version`（输出 `SERVER_VERSION`）；否则桌面端只能靠文件名猜版本。
- 读 `manifest.json` 需要一个轻量 JSON 读取函数：桌面端已有 `serde_json`，直接 `include_str!`
  或运行时读包内文件皆可，但要处理"用户手工改过扩展目录"的情况（读不到就显示「未知」而不是报错）。
