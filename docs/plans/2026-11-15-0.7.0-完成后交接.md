## 五分钟跑起来

本机 **cargo 不在默认 PATH**：

```powershell
$bin = "$env:USERPROFILE\.rustup\toolchains\stable-x86_64-pc-windows-msvc\bin"; $env:PATH = "$bin;$env:PATH"
cd E:\WorkSpace\projects\tool\dlm
cargo build --bin dlm-gui
```

**门禁一条命令**（会自己设好 `DLM_NO_TRAY` / `DLM_NO_SHELL_OPEN` / `DLM_NO_POPUP` / `DLM_NO_UPDATE_CHECK`）：

```powershell
cd E:\WorkSpace\projects\tool\dlm
powershell -NoProfile -ExecutionPolicy Bypass -File .\gates.ps1
# 结尾打印 GATES PASSED；-SkipIntegration 可跳过较慢的集成门
```

**起一个可截图的 GUI**（用 `target\visual-stage1` 里的夹具；端口随意但要避开占用）：

```powershell
$root = 'E:\WorkSpace\projects\tool\dlm\target\visual-stage1'
$env:DLM_NO_TRAY='1'; $env:DLM_NO_SHELL_OPEN='1'
Start-Process -FilePath '.\target\debug\dlm-gui.exe' -ArgumentList @('--port','47230',
  '--queue',"$root\queue.json",'--out-dir',"$root\dl",'--log-dir',"$root\logs",
  '--endpoint',"$root\endpoint.json",'--token','dev','--concurrency','2')
```

队列空了就通过 HTTP 造任务（**token 参数名是 `t`，不是 `token`**）：

```powershell
Invoke-RestMethod -Method Post -Uri "http://127.0.0.1:47230/api/add?t=dev" `
  -ContentType 'application/json' -Body '{"url":"http://127.0.0.1:1/a.iso","name":"a.iso"}'
```

**截图与点击**走 `agent-desktop` MCP（headless 下**禁止物理鼠标**，只能走无障碍）：

```
desktop_list_windows app=dlm-gui.exe        → 拿 window_id
desktop_screenshot window_id=<id> output_path=...png
desktop_find app=dlm-gui.exe role=button name=设置   → 拿 ref
desktop_click ref_id=@<snapshot>:e1
```

**ref 会过期**。点了没反应先怀疑 ref 过期（重新 `find`/`snapshot`），别怀疑代码——
我为此误判过一次"自绘控件收不到 click"，后来证实是旧 ref。

## 必须知道的坑（都是这轮实测撞出来的）

### egui 0.37 的语义

- `Window::open(&mut b)` 的**初值就是"是否打开"**。传 `&mut false` ⇒ 整帧跳过绘制。
  命令面板曾因此"快捷键明明触发、面板不出现"。
- `TextEdit::frame` 收的是 `Frame` 不是 `bool`（0.36 是 bool）。无边框写 `.frame(egui::Frame::NONE)`。
- `WidgetType` 已废弃 → `egui::Role`（`accesskit::Role` 的再导出）。
- `Response::context_menu(|ui| …)` 还在，右键菜单用它。

### 主题：只 `set_visuals` 不够

eframe 会按系统外观重新应用主题，把 `set_visuals` 顶掉。表现是**同一帧两套配色并存**
（一半深一半浅）。三件一起做才对：

1. `ctx.set_theme(Dark/Light)` —— 定下"这套配色的身份"
2. `ctx.set_visuals(...)` —— 改当前这份
3. 每帧比 `ctx.theme()` 与全局开关，不一致就拉回来（`app/mod.rs` 帧首那段自愈）

`theme::apply_preference("system")` 靠 `Context::default().system_theme()`，拿不到就按浅色。

### 无障碍：角色决定能不能被点

- `Role::Button` + `Invoke` → **egui 接得住**，自绘也行（只要 `Sense::click` + `widget_info`）。
- `Role::CheckBox` 收到的是 `LegacyIAccessible.DoDefaultAction` → **只有真 `egui::Checkbox` 认**。
  自绘版"树里有、点不动"。所以列表里的勾选框是真控件。
- 同一窗口内多个控件**同名**会让自动化认不出（`AMBIGUOUS_TARGET`）。勾选框的无障碍名带任务名。
- 画出来的控件**默认不在树里**，要主动 `response.widget_info(|| WidgetInfo::labeled(...))`。

### 字体：这六个字符 YaHei 没有字形

`▾ ✓ ✕ ⋯ ＋ ▶`（还有 `①②③`）画出来是方框。**一律自绘**（`icons::draw_icon`），
用例 `every_symbol_we_put_in_the_ui_has_a_glyph` 守着。数字方块也是画的。

### 行结尾：`/src/gui/**` 是 LF

用 CRLF 锚点做字符串替换会静默不生效（`Replace` 不报错）。要么用 `"`n"` 锚，
要么按行号手术 —— 但**行号手术改 HTML 时把结构改坏过一次**，改完必须重新打开看。

### 表格列宽：行与表头必须共用一份排布

`list.rs` 的 `columns(rect)` 是唯一来源。各算一次的下场是"右栏一开，进度条压到文件名上"。

### 仓库结构：`main` 是发布通道，不是主干

`origin/main` **只有 `README.md` + `latest.json`**，与代码分支是**两条不相干的历史**。

发版顺序（`main` 上的 README 写着同样的流程）：

1. 代码分支跑门禁 → `packaging\build-package.ps1`（先改 `gui::RELEASE`，脚本会校验一致）
2. `gh release create v<rel>` 上传 zip
3. **之后**才更新并推送 `main/latest.json`（顺序反了用户点更新就是 404）

⚠️ **不要在 `main` 上跑 `git add -A`** —— 那会把整棵树（含 `target/`）加进去。我干过一次，
已 reset 掉、远端未污染，但别再来第二遍。

## 两个新踩的坑（写下来省下次）

1. **跑门禁前必须关掉自己起的 GUI**：集成门替换 `target\debug\dlm-gui.exe` 时会被运行中的
   实例锁住，报 `failed to remove file ... 拒绝访问 (os error 5)`，看着像集成用例挂了。
2. **变异验证还原文件后要 `touch` 一次**：`Move-Item` 还原的文件 mtime 比上次编译还旧，
   cargo 按 mtime 判定"没变"，会复用**变异版**的目标文件 —— 于是你看到的是变异结果，
   会误判成"还原后还是红的"。变异与还原两次都得刷新时间戳。
