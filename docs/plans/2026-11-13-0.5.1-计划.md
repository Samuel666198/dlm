# 0.5.1 计划（2026-11-13，更新面板与扩展同步）

> 起因：0.3.1 → 0.5.0 自更新实测成功，但更新面板上「磁盘上还是 0.2.14」这句话
> 与实际不符 —— 需要先纠正认知，再改界面。

## 事实核对（2026-11-13 20:20）

| 项 | 实测 |
|---|---|
| 版本标记 | `%LOCALAPPDATA%\dlm\installed.json` = `{release: 0.5.0, core: 0.1.0, extension: 0.2.16}` |
| 磁盘扩展 | `%LOCALAPPDATA%\dlm\extension\manifest.json` = **0.2.16**（`background-0.2.16.js` 等） |
| 结论 | **更新器确实会同步扩展**（`updater::install_extension`，包内路径 `browser/extension`） |

所以之前"自更新只换 exe、不换扩展"的说法是**错的**；面板那句"磁盘上还是 0.2.14"是
**更新开始前的快照**，更新完成后没有刷新。

## 任务 1：更新面板的扩展行改成"两个版本分开说"（必做）

- 现在把两件事混成一句：磁盘版本（更新器负责）与浏览器正在跑的版本（用户手动重载才变）
- 改成两行：
  - `扩展文件 0.2.16（已就位）`
  - `浏览器正在运行 0.2.14 — 请到扩展页点一次「重新加载」`
- 并在**更新完成后重新读一次**磁盘版本，不拿启动时的快照说话
- 判据：`view` 的构造有测试覆盖"磁盘版本与浏览器版本不同"这一组合；文案不再出现"磁盘上还是"

## 任务 2：更新后自动提示重载（可选）

- 更新成功、进程重启后，若 `扩展磁盘版本 != 浏览器上报版本`，在状态栏挂一条常驻提示，
  直到版本一致自动消失
- 判据：纯函数 `needs_reload(disk, browser) -> bool` 有测试

## 任务 3：文档纠偏

- 在 `docs/evidence/` 里补一条：更新器会同步扩展；此前"只换 exe"的记录作废
- 交接文档里更新流程一节同步改写
