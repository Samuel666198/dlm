# 0.4.0 计划（按优先级，2026-11-13）

> 顺序按"先校准 → 先补坑 → 再上大件"排：**C1 → E1/E2 → A → B → D**
> 纪律：每阶段一提交、每阶段跑 `gates.ps1`（lib 只增不减，当前 404）；扩展改动必须 `node --check` + 静态检查；发布需用户点头。

## C1 · IDM 分段/并发实测（分析，半天）— 最高优先

**为什么先做**：它决定引擎参数（`min_seg`、并发上限、动态分裂阈值）是否合理，后面所有下载行为都吃这组数。

- 方法：本地受控 HTTP 服务（固定大小文件 + Range 支持）→ 让 IDM 下载 → 观察连接数曲线、分段边界、断开重连时机
- 判据：给出"IDM 在 N 秒内开了几条连接、每段多大、什么时候重分段"的可复现记录
- 产出：`docs/evidence/2026-11-14-IDM分段实测.md`，并与 dlm 现值对照，给出"改/不改"的结论
- 边界：只读观察 + 本地服务，不碰驱动、不改 IDM

## E1 · 接管失败要说清原因（小）

**问题**：`POST` 表单下载、`blob:`/`data:` 下载现在**静默不接**，用户不知道为什么没进 dlm。

- `takeover.js`：`shouldTakeover` 补 `blob` / `data` / `post` 三类明确原因
- 选项页显示"最近一次接管"：时间 + 结果（成功 / 跳过 + 原因）
- 判据：原因字符串可被单测断言；选项页不显示 `undefined`

## E2 · 接管回执超时的可见化（小）

- 已有 `lastTakeover.reason = "no-ack"`，但只在存储里；选项页显示"上次接管未确认（宿主没响应），浏览器下载已保留"
- 判据：无回执时 `lastTakeover.ok === false` 且 reason 可读

## A · 站点抓取 Grabber（0.4.0 主体）

- 输入：起始 URL、深度 1–3、同域开关、包含/排除通配、页数/文件数/总字节上限
- 流程：抓页面 → 提取 `<a href>` / `<img src>` / `<video src>` → 过滤 → **先出清单（不下载）** → 勾选入队
- 礼貌：读 `robots.txt`、单域并发 1、可配延迟
- 判据：链接提取与通配是纯函数；"只列清单"独立可测；不跟随 `mailto:`/`javascript:`

## B · 视频嗅探增强（路线 1 收尾）

- MPD/DASH **只识别不下载**，列表标注"需外部工具"；HLS 补 `application/vnd.apple.mpegurl` 等 MIME 变体
- 判据：识别不执行页面 JS、不破解签名；点不可下载项时给出明确提示而不是静默失败

## D · 体验补完（挑做）

- 托盘气泡（收进托盘时告知"还在下"）
- 详情页补：校验和、平均速度、实际落点
- 限速计划（按时间段切换）
- 代理支持（HTTP/SOCKS5，按任务或全局）

## 风险与回退

| 风险 | 回退 |
|---|---|
| C1 实验影响用户网络/IDM | 只用本地回环服务，限速小文件，随时可停 |
| 接管原因误判 | 只加"解释"，不改接管决策；默认仍不接 |
| Grabber 拖垮站点 | 三重上限 + 单域并发 1 + 延迟 |
| 抓取内容合规 | 只抓公开页面，遵守 robots，不做登录态爬取 |
