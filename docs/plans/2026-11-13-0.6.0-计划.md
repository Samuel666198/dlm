规则这条链路的事实（下个会话不用再摸一遍）：

- **落点算在入队那一刻**：`rules::dir_path_for(url, &tuning.rules, &tuning.out_dir)` →
  `store.add_with_dir(..., Some(dir))` 钉到 `Task.dir`；连接数**每次派发**现算（改规则不必重排队）。
- **只有一个出口**：`runner::plan_for_task(task, tuning) -> (落点, 连接数)`。子进程 argv 的
  `--out-dir` / `--connections`、host 预算的条数、进度采样、`TaskView.path`、reveal、
  完成后扫描，全部经 `Task::dir_in(&tuning.out_dir)` 或这个出口 —— 不许再直接拿 `tuning.out_dir`。
- 规则里写**相对目录** ⇒ 接到默认落点下面（`out_dir\视频`），不按 cwd 解析。
- **没命中就不钉**（`rule_dir == out_dir` 时 `Task.dir` 留 `None`）⇒ 改设置里的保存目录，
  排队任务照旧跟着走，与改规则不搬家是两件事。
- 顺序 = 优先级，先命中先用（`rules::match_rule`）。
