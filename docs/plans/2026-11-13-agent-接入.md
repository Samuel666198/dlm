# dlm × AI Agent：CLI 与 MCP 接入方案（0.6.0）

> 用户拍板的两个前提，代码必须遵守：
> 1. **不弹窗**。确认发生在对话里，由 Agent 回头问人 —— GUI 只在历史里留一条被动记录。
> 2. **失败一律结构化返回**，由 Agent 自己解释给人听，不靠界面兜底。

## 顺序

1. `dlm --json`（半天）—— 所有 Agent 立刻可用，也是 MCP 的底座
2. GUI 本地控制口（1 天）—— `127.0.0.1` + 随机 token
3. `dlm-mcp`（1 天）—— stdio MCP，7 个工具

## 安全边界

| 项 | 规则 |
|---|---|
| 监听 | 只绑 `127.0.0.1`，**永不 `0.0.0.0`** |
| 凭据 | 每次启动生成随机 token → `%LOCALAPPDATA%\dlm\control.token`（仅当前用户可读）；随重启轮换 |
| 日志 | token **永不**写入日志、错误串、界面 |
| 生命周期 | GUI 退出即端口消失；控制口不常驻后台 |

## 二次确认（核心设计）

不弹窗，改成**带票据的两步**：

```
Agent: add_download(url, dir?)
  → {status:"pending_approval", approval_id:"ap_7f3c", expires_in:300,
     summary:"下载 ubuntu-24.04.iso 到 D:\Downloads（6.1 GB）"}

Agent（必须先问人，再调）: confirm_download(approval_id:"ap_7f3c")
  → {status:"queued", task_id:"t_91ab"}
```

规则：

- `approval_id` **一次性**，用完即废；5 分钟过期
- 票据**绑定参数**：URL 与落点必须和申请时完全一致，改一个字节就作废（防"确认 A 却装了 B"）
- `grab_site` 同样两步：先返回清单，人看过再 `confirm_grab(approval_id, picked_indices)`
- 设置 `agent_auto_approve = true` 时跳过票据，直接入队（默认 **关**）
- GUI 端只写一条历史：`14:22 agent 请求下载 …（待确认 / 已确认 / 已过期）`，**不弹窗、不抢焦点**

## 错误形状

```json
{"error":{"code":"DISK_FULL","message":"目标磁盘剩余 1.2 GB，任务需要 6.1 GB","detail":{"free":1288490188,"need":6550000000}}}
```

`code` 固定枚举：`BAD_URL` · `NO_SUCH_DIR` · `DISK_FULL` · `DUPLICATE` · `APPROVAL_EXPIRED` · `APPROVAL_MISMATCH` · `NOT_FOUND` · `BUSY` · `INTERNAL`。

## MCP 工具表

| 工具 | 说明 | 是否需要确认 |
|---|---|---|
| `add_download` | 入队一个下载 | 是（默认） |
| `confirm_download` | 用票据确认 | — |
| `list_tasks` | 任务列表（含速度、落点、错误） | 否 |
| `pause_task` / `resume_task` / `remove_task` | 单任务控制 | 否 |
| `set_speed_limit` | 全局限速（可带时间窗口） | 否 |
| `grab_site` | 抓站点，**只返回清单** | 否（只读） |
| `confirm_grab` | 按勾选入队 | 是 |

## 明确不做

- 不提供"执行任意命令"的工具（只做下载相关）
- 不让 Agent 改设置（限速除外）
- 不在 GUI 里为 Agent 单独开一个任务区：Agent 的任务与手动任务同一个队列
